# MLOps — ML 管线工作流

把机器学习当软件工程做：可复现、可测试、可部署、可监控。

## 何时用

- 搭建 ML 训练/推理管线
- 模型部署与上线
- 建立可复现训练流程
- 模型监控与回归

## 管线全流程

```
数据 → 预处理/特征 → 训练 → 评估 → 注册 → 部署 → 监控
  ↑___________________ 反馈循环（新数据/漂移）________________↓
```

### 1. 数据与特征

- 数据版本化（dataset 版本、schema 记录）。
- 训练/验证/测试严格分离（不泄漏）。
- 特征工程代码化、可复现；特征与训练版本绑定。

### 2. 训练

- **可复现**：固定随机种子、依赖版本、环境（容器）。
- 训练配置入库（超参数/数据版本/代码 commit 记录）。
- 实验跟踪：每次实验记录指标与配置（对比基线）。

### 3. 评估

- 离线评估：准确率/精确率/召回率/F1 + 业务指标（参考 llm-eval 思路）。
- 上线前门槛：新模型必须 ≥ 基线（同测试集对比）。
- 切片评估：关键子群体（新用户/冷门类目）单独看，不只看总体。

### 4. 注册与部署

- 模型注册：版本、指标、审批记录（谁批准、依据什么）。
- 部署策略：shadow（影子流量对比）→ canary → full（参考 shipping）。
- 回滚：旧版本随时可切回。

### 5. 监控与反馈

- **数据漂移**：输入分布变化检测（训练 vs 在线）。
- **概念漂移**：模型表现随时间下降。
- **推理监控**：延迟、错误率、异常输出（参考 observability）。
- **反馈闭环**：监控到漂移 → 触发重训/人工评审。

## 工程纪律

- 一切皆代码：数据、训练、评估、部署配置都入库可评审。
- CI/CD 接入：训练管线、评估门槛自动化。
- 失败可恢复：管线断点续跑、幂等。
- 文档：每个模型有卡片（用途/数据/指标/局限）。

## 交付清单

- [ ] 管线端到端可跑（一条命令）
- [ ] 训练可复现（种子/版本/环境锁定）
- [ ] 评估有门槛 + 切片检查
- [ ] 部署有 shadow/canary 与回滚
- [ ] 漂移监控已配置
- [ ] 模型卡片齐全

## 边界

- 具体框架（MLflow/Kubeflow/Airflow）按项目栈选型。
- 小模型/简单场景可简化流程（不要为了 MLOps 而 MLOps）。
