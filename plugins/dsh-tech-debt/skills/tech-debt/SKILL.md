# Tech Debt — 技术债治理

把技术债当财务债管理：审计 → 分类 → 按利息偿还 → 防再借。

## 何时用

- 技术债审计与盘点
- 依赖审计（过期/废弃/安全漏洞）
- 清理废弃代码与重复
- 决定还债优先级
- 建立债务管理流程

## 1. 债务审计

- **依赖**：过期大版本、废弃包、安全漏洞（npm audit/pip-audit 类）、
  未使用依赖（depcheck 类）
- **代码**：废弃/死代码（未被引用）、重复实现、TODO/FIXME 积压、
  缺陷标记（eslint-disable/ts-ignore 滥用）
- **架构**：循环依赖、上帝对象、违反分层

## 2. 分类与优先级

每笔债评估三个维度：
- **利息**：每周/月为这笔债付出多少（改 bug 成本/性能损失/安全风险）
- **风险**：不还的后果（崩溃/漏洞/无法升级）
- **偿还成本**：现在还 vs 以后还的代价差

**优先**：利息高 + 风险大 + 现在还便宜（趁小趁早）。
**推迟**：利息低 + 无风险 + 还债会阻塞主线（记录待还）。

## 3. 偿还策略

- **增量还债**：每笔改动顺手清理相关债务（不搞大爆炸重写）
- **围栏隔离**：无法立即还的债圈定边界（接口收窄），防扩散
- 大债拆小：一次一个模块/服务
- 测试先行：还债前有行为契约（重构才安全）

## 4. 债务登记与防再借

- 债务登记表：债务项/利息评估/负责人/偿还计划（Tech Debt 看板）
- 评审门槛：新代码不引入同类债（lint/架构测试自动拦）
- 定期复评：每季度重估利息与优先级

## 5. 自查清单

- [ ] 依赖/死代码/缺陷标记已审计
- [ ] 每笔债有利息/风险/偿还成本评估
- [ ] 还债按增量 + 测试先行
- [ ] 大债拆小、无法还的已围栏
- [ ] 债务登记表维护中
- [ ] 新债被评审/自动检查拦截

## 边界

- 技术债不全是坏事：有意的债换取交付速度是合理取舍，要显式记账。
- 治理节奏匹配团队：债表要轻，别变成官僚流程。
