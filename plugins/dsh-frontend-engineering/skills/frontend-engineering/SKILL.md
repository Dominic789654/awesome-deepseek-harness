# Frontend Engineering — 前端 UI 工程

把前端当工程做：组件设计、状态管理、数据获取、性能、可维护性。
与 frontend-design 互补（那个管"设计好看"，本技能管"实现正确"）。

## 何时用

- 搭建前端工程结构
- 设计组件体系
- 选择/落地状态管理
- 实现数据获取模式
- 前端性能与可维护性优化

## 1. 组件设计

- **单一职责**：一个组件一件事；可复用部分提取，但不过早抽象。
- **组合优于继承**：用 props/children 组合，少用继承/高阶组件包裹层。
- **props 即契约**：命名清晰、默认值明确、必填/可选显式（参考 api-design）。
- **状态就近**：UI 状态放需要它的最近处；全局共享才提升。
- **受控组件**：表单/输入用受控模式（数据流单向）。

## 2. 状态管理

| 场景 | 方案 |
|---|---|
| 组件局部状态 | useState/ref（就近） |
| 跨组件共享 | context + reducer（适度） |
| 服务端数据 | 数据获取库（SWR/React Query 等）缓存 |
| 全局复杂状态 | 状态库（zustand/redux 等，谨慎引入） |

**纪律**：
- 能就近不放全局；加全局状态是承诺，想清楚再上。
- 派生状态不重复存储（能从现有状态算出来的不存）。
- 状态更新可预测（reducer 模式对复杂逻辑）。

## 3. 数据获取

- 用框架推荐模式（参考 source-driven 技能查官方文档）。
- 处理四态：加载中/成功/空/错误（都有 UI 呈现）。
- 缓存与失效策略明确；避免请求瀑布（并行请求合并）。
- 竞态防护：请求返回顺序错乱时的处理（最新请求优先）。

## 4. 性能与可维护性

- 参考 performance 技能（懒加载/代码分割/虚拟列表）。
- 组件重渲染最小化：memo 适度（不要到处 memo）。
- key 使用稳定唯一值（不用 index 当 key 处理可变列表）。
- 样式方案统一（CSS Modules/Tailwind/CSS-in-JS 选一，混用是债）。
- 可访问性内置（语义标签/键盘/对比度，参考 a11y-audit）。

## 5. 工程结构

- 目录按功能组织（feature-based），非按类型堆叠。
- 公共组件/工具与业务组件分离。
- 路由/页面与组件分层清晰。
- 测试策略：组件测试 + 关键路径 E2E（参考 tdd）。

## 交付自查

- [ ] 组件职责单一、props 契约清晰
- [ ] 状态管理适度（无过度全局化）
- [ ] 数据获取四态齐全、无请求瀑布
- [ ] 性能关键点已处理（大列表/大图/懒加载）
- [ ] 可访问性基础到位
- [ ] 目录结构符合团队约定

## 边界

- 技术栈（React/Vue/Svelte）按项目实际；本技能提供通用工程原则。
- 与前端相关的既有约定优先遵循，不强行改造。
