# Operating Kit — 会话操作纪律

会话开始简报 + 结束收尾：让每个新会话从正确上下文开始。

## 何时用

- 每个重要工作会话开始时（防陈旧状态错误）
- 会话结束时（收尾：经验/未决问题/下一步）
- 从崩溃/强制退出恢复（上次没跑收尾）
- 外部部署/CI 造成状态漂移后对账

## 1. 会话开始简报

1. **读状态文档**：项目单一事实源（版本/已部署修订/未决问题/下一步）
2. **验证线上状态**（别只信文档）：跑最便宜的实时确认命令
3. **检查工作树**：`git status --short && git log --oneline -10`
   ——有文档未记录的提交/部署，或上次会话可能没收尾 → 对账：
   以线上为权威，定向更新状态文档（部署修订/最后已知好版本）；
   标注哪些是推断、哪些是显式记录
4. **先标记不匹配再干活**："MISMATCH. 状态文档说 X 但线上是 Y"，
   对账或确认后再动手

**输出**（简报格式）：版本/线上检查（匹配或 MISMATCH）/
已知问题/下一步/未提交变更/最近提交/恢复说明。保持简短，是状态检查不是报告。

## 2. 会话结束收尾

**捕捉**（从对话推断或询问）：
- 工作状态变化（开始/完成/阻塞）
- 新发现的已知问题
- 未写入状态文档的配置/功能开关/环境变更
- 值得存入记忆的持久经验
- 下一会话的下一步

**步骤**：读状态文档 + 记忆索引 → 只定位本次会话变旧的字段 →
**定向编辑**（不整文件替换；部署已更新版本字段就不重写）→
更新记忆索引（当前状态行/新经验一行指针）→ 确认（逐文件报旧值→新值）。

**规则**：
- 无重大变化（纯探索）→ 说明并跳过编辑
- 重要事件发生时即时写，收尾只是补漏
- 对"已添加/已配置/已部署"的说法**信任但验证**（对照线上再记录）

## 3. 自查清单

- [ ] 开始时读了状态文档 + 跑了线上验证
- [ ] MISMATCH 已标记并对账（标注推断 vs 显式）
- [ ] 收尾只更新变旧字段（定向编辑）
- [ ] 经验/问题/下一步已记录
- [ ] 部署状态未被重复改写（除非线上不符）
- [ ] 无重大变化时明确跳过

## 边界

- 状态文档是"单事实源"：项目要有它才能用本技能。
- 是纪律不是流程重：简报/收尾都要短，别写成报告。
