# DB Migration — 数据库迁移

安全地变更数据库 schema 与数据：可前滚、可回滚、不宕机、不丢数据。

## 何时用

- 修改表结构（加/删字段、改类型）
- 数据迁移（合并/转换/回填）
- 索引变更
- 大规模数据操作

## 1. 迁移流程

1. **评估**：改动影响（表大小、锁、流量、下游依赖）。
2. **写迁移脚本**：前滚（up）+ 回滚（down）成对编写。
3. **评审**：走代码评审（downtime 风险、锁、幂等）。
4. **备份**：迁移前备份（可恢复点）。
5. **灰度执行**：先 staging/低峰，再生产。
6. **验证**：数据一致性校验 + 应用兼容性。

## 2. 迁移脚本规范

```sql
-- up（前滚）
ALTER TABLE users ADD COLUMN timezone TEXT NOT NULL DEFAULT 'UTC';

-- down（回滚）
ALTER TABLE users DROP COLUMN timezone;
```

- **成对编写**：up/down 必成对（能回滚）。
- **幂等**：重复执行结果一致（`IF NOT EXISTS` / 检查后再执行）。
- **小步**：大变更拆多个小迁移（参考 incremental）。
- **不破坏现有应用**：先加后删（expand-contract）——
  1. 加新字段/新表（应用继续用旧逻辑）
  2. 应用切换到新结构
  3. 删除旧字段/旧表

## 3. 不宕机变更模式

| 变更 | 安全做法 |
|---|---|
| 加字段（可空/有默认） | 直接加（多数库快） |
| 加字段（NOT NULL 无默认） | 先加可空 → 回填 → 设 NOT NULL |
| 改字段类型 | 加新列 → 双写/回填 → 切换 → 删旧列 |
| 删字段 | 先停用应用引用 → 再删 |
| 大表加索引 | 在线建索引（CONCURRENTLY）或分批 |
| 数据回填 | 分批+限速，避免长锁 |

## 4. 数据一致性校验

- 迁移前后：行数、校验和（checksum）、抽样对比。
- 双写期间：新旧结构数据对比（对账任务）。
- 校验失败：回滚或修复（迁移脚本本身可重跑）。

## 5. 回滚

- 每个迁移有 down 脚本（数据迁移的回滚尤其要小心：被覆盖的数据
  不可逆 → 迁移前备份）。
- 回滚优先于"现场修补"（生产环境）。

## 自查清单

- [ ] up/down 成对编写
- [ ] 迁移幂等
- [ ] 大表操作避开高峰期 + 在线方式
- [ ] 迁移前有备份
- [ ] 数据一致性校验已定义
- [ ] expand-contract（先加后删）已考虑

## 边界

- 具体数据库（PG/MySQL）语法与锁行为不同，按库确认。
- 涉及生产数据迁移需用户/团队批准执行。
