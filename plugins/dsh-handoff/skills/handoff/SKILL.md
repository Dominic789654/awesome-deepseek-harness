# Handoff — 会话交接文档

把当前会话浓缩成交接文档，让一个全新会话/agent 能无缝接手继续工作。

## 何时用

- 结束一段长工作时，把进度交给下一个会话
- 切换 agent 或让子代理接手
- 用户说"交接" / "明天继续" / "换个会话继续"
- 用户传入参数时：把参数当作"下一个会话要做什么"的描述，据此定制文档

## 文档结构

```markdown
# 交接文档：<任务名>

## 状态
- 目标：<要完成什么>
- 当前进展：<已完成 / 进行中 / 阻塞>

## 关键决策
- <已定决策 + 为什么>（引用来源：spec/ADR/issue/commit）

## 下一步
- [ ] <待办 1>（负责人：谁）
- [ ] <待办 2>

## 建议技能
- <下一个会话应该调用的技能/工具清单>

## 引用产物（不重复内容）
- <spec / 计划 / ADR / issue / commit / diff 的路径或 URL>

## 风险与注意
- <阻塞项、坑、待确认事项>
```

## 写作纪律

1. **不重复已有产物**：spec、计划、ADR、issue、commit、diff 里已有的内容
   不抄进交接文档，用路径/URL 引用。
2. **含"建议技能"区**：明确写出下一个会话该调用哪些技能/工具。
3. **脱敏**：API 密钥、密码、可识别个人信息一律不写入（用占位符代替）。
4. **可执行**：交接文档的"下一步"必须是明确可执行的动作，不是模糊愿望。
5. **存到临时目录**（用户 OS 的临时目录），不污染当前工作区
   （除非用户明确要求放工作区）。

## 与 DSH 的配合

- DSH/CC 的长期记忆形态是交接档案（如 `handover-brief.md`）——本技能
  生成的内容可作为其素材，或直接按用户约定路径保存。
- 交接文档写给"全新上下文"的读者：假设对方对本会话一无所知，
  但能读到引用的产物。
