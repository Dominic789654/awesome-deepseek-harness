# Writing For Agents — 写给 agent 的文档

写任何 agent 消费的文档（技能、AGENTS.md/CLAUDE.md、指针指向的文档）。
包装不同，写法相同：agent 每次运行走同一过程，杠杆一致。

## 1. 上下文指针

**指针** = 上下文里指向外部材料的引用，其**措辞**（而非目标）决定 agent
何时、多可靠地取到材料。指针做两件事：说明材料是什么 + 列出触发**分支**
（文档处理的不同情况）。

- **前置领航词**：指针的触发工作发生在开头
- **一分支一触发**：同义词只是同一分支写两遍，合并只留真正不同的分支
- 常驻指针每个字都烧 token：剪枝比正文更狠

## 2. 双层预算

- **上下文负载**：常驻材料的成本（每轮烧 token 与注意力）
- **认知负载**：人的成本（知道有哪些文档、何时取用）——人是指引索引，
  不是要最小化的成本，是人的自主权定价；只在人判断力该起作用的地方花

指针指向的材料逃离上下文负载（只付指针一行）；无指针材料全压在认知负载。

## 3. 信息层级

内容两种：**步骤**（有序动作）与**参考**（按需查阅的定义/规则/事实）。

层级阶梯：① 文件内步骤（主层）→ ② 文件内参考（按需查阅）→
③ 披露参考（推出到独立文件，指针触发才加载）。

- **渐进披露**：把下层的材料推到指针后面，让顶层可读——不只是省 token，
  是保护层级本身。分支是最好的披露测试：所有分支都要的留在内联，
  只有部分分支要的推到指针后
- **就近聚合**：概念的定义/规则/注意事项放同一标题下，读一处带出邻居
- **蔓延** = 失败模式：文档太长，即使每行都有用——用阶梯披露 + 按分支拆

## 4. 步骤与完成标准

每个步骤以**完成标准**收尾（告诉 agent 工作何时算完成）：
- **清晰度**：agent 能区分完成/未完成。模糊边界（"理解达成"）诱发
  **提前完成**——先收紧边界（本地且便宜），仍模糊且观察到赶进度才
  拆分序列隐藏后续步骤
- **需求度**：要求多少。"每个改动模型都交代"比"产出变更列表"更有力
- 最强的标准：**可检查 + 穷尽**

## 5. 领航词与正向表达

**领航词** = 预训练里已有的紧凑概念（"教训""战争迷雾""曳光弹"），
以 token 重复而非句子，用最少 token 锚定整片行为。自造词可行但要定义，
且不招募先验——先找现成词。

- 正文里锚定执行；指针里锚定调用（prompt/文档/代码库同词，取用更可靠）
- 找机会重构为领航词："fast, deterministic, low-overhead" → *tight*

**否定是失败模式**：禁止式表达把被禁行为拉进上下文反而更可得
（"别想大象"满脑子都是大象）。**写正向目标**（"写单行注释"），
禁令只在无法正向表达时作为硬护栏，且必须配正向目标。

## 6. 剪枝

- **单一事实源**：一个含义一个权威位置，改行为是一处编辑
- **环境也是事实源**：文档复述环境（package.json/--help）就是缓存，
  只在查找昂贵时才值得。缓存环境查不到的东西（未写出的约定/理由/坑）
- **相关性**：每行是否还起作用；无剪枝纪律的默认结局是**沉积**
  （加安全删有风险，陈层堆积）

## 7. 自查清单

- [ ] 指针措辞前置触发、一分支一触发
- [ ] 常驻材料剪到最瘦（上下文负载可控）
- [ ] 步骤/参考/披露层级分明、就近聚合
- [ ] 完成标准可检查且穷尽
- [ ] 领航词已用、无否定式表达
- [ ] 单一事实源、无复述环境的缓存文档

## 边界

- 写法通用（技能/AGENTS.md/文档同杠杆）；技能特有机制（frontmatter/
  调用选择）另看技能机制文档。
- 优先级：先收窄指针措辞（便宜），内联材料是最后手段。
