# Data Quality — 数据质量框架

用校验规则、数据契约与监控确保数据管线可靠——脏数据进系统的代价远高于
早发现早修复。

## 何时用

- 在管线里加数据质量检查
- 建立校验规则
- 建立跨团队数据契约
- 监控数据质量指标
- 在 CI/CD 里自动化数据校验

## 1. 校验规则（按优先级）

| 规则 | 说明 | 示例 |
|---|---|---|
| 完整性 | 必填字段非空 | 订单号非空 |
| 唯一性 | 无重复 | 用户 ID 唯一 |
| 类型 | 字段类型正确 | 金额是数值 |
| 范围 | 值在合理区间 | 年龄 0-120 |
| 格式 | 符合格式 | 邮箱格式 |
| 一致性 | 跨表一致 | 外键都存在 |
| 时效性 | 数据新鲜 | 昨日数据已到 |
| 自定义业务规则 | 业务约束 | 折扣 ≤ 30% |

## 2. 数据契约（跨团队）

- **定义契约**：字段名、类型、含义、必填性、生产者/消费者约定。
- **契约即测试**：生产方变更破坏契约 → CI 拦截，消费者不受突袭。
- **版本化**：契约变更走版本（加字段向后兼容，破坏性变更需协调）。
- **文档化**：契约就是文档（字段含义、来源、口径）。

## 3. 质量监控

- **告警**：质量指标跌破阈值 → 告警（参考 observability/slo）。
- **追踪**：每日质量评分趋势（完整性/唯一性/新鲜度）。
- **根因**：质量下降 → 定位来源（上游表/ETL 逻辑/数据源）。

## 4. CI 自动化

- 关键表/流入数据在 CI 跑校验（失败即阻断）。
- 新增数据源/字段 → 同时加校验规则。
- 校验规则本身入库（代码化），可评审可回滚。

## 实现清单

- [ ] 关键表有完整性/唯一性/类型校验
- [ ] 核心业务字段有范围/格式/业务规则校验
- [ ] 跨表一致性检查（外键/参照）
- [ ] 数据新鲜度监控（批处理/流）
- [ ] 契约变更走版本 + 协调
- [ ] 质量指标有告警与趋势追踪

## 边界

- 校验工具（Great Expectations/dbt tests/自研）按项目栈选型。
- 质量规则过度会拖慢管线：优先保护"下游会坏"的关键字段。
