# Prototype — 原型验证

原型 = **回答问题的可丢弃代码**。问题决定形态。

## 何时用

- 验证状态模型/逻辑"感觉对不对"
- 探索 UI 应该长什么样
- 在设计决策前快速获得手感

## 1. 选分支（问题决定形态）

- **"逻辑/状态模型感觉对吗？"** → 构建单一可分享 HTML 文件：
  自由操作按钮 + 标签页引导走查，把状态机推到纸上难推理的
  案例，非开发者也能驱动
- **"应该长什么样？"** → 同一路由生成几个**截然不同**的 UI 变体，
  用 URL 参数 + 浮动底栏切换

选错分支浪费整个原型：真模糊且用户不在 → 按周围代码默认
（后端模块 → 逻辑；页面/组件 → UI），并在原型顶部声明假设。

## 2. 通用规则

1. **从第一天就是可丢弃的**，并明确标注：放在实际使用处附近（上下文
   明显），命名让读者看出是原型非生产；UI 路由遵循项目现有约定
2. **一次运行**：一个命令（`pnpm <name>`/`python <path>`）或双击 HTML，
   无需思考即可启动
3. **默认无持久化**：状态在内存；持久化是原型在**检验**的东西，
   不是它依赖的东西；涉及 DB 时用 scratch DB/本地文件（名字带
   "PROTOTYPE, wipe me"）
4. **跳过打磨**：不写测试、不做过量错误处理、不做抽象——快速学到东西
5. **表面化状态**：每次动作/变体切换后打印完整相关状态，用户能看到变化
6. **完成后捕获**：把验证过的决策并入真代码；原型本身作为**一手来源**
   提交到可丢弃分支（不进 main），并在实现 issue 上留指向该分支的
   上下文指针；答案（结论 + 它解决的疑问）记入 issue 或 commit。
   main 只保留验证过的决策

## 3. 自查清单

- [ ] 分支选对（逻辑 vs UI），假设已声明
- [ ] 明确标记可丢弃、位置贴近实际使用处
- [ ] 一条命令/双击可运行
- [ ] 无持久化（除非在检验持久化本身）
- [ ] 状态表面化（每次动作可见）
- [ ] 验证决策并入真代码 + 原型归档留指针

## 边界

- 原型是"快学习"工具：别让它长成生产代码（小心"原型漂移"）。
- 与增量实现互补：原型回答"对不对"，生产实现才讲纪律。
