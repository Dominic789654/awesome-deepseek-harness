# Error Handling — 错误处理模式

系统化处理错误：分层、类型化、优雅失败、可观测、可恢复。

## 何时用

- 设计错误处理策略
- 类型化/统一错误格式
- 实现优雅降级
- 错误可观测性（日志/指标）
- 错误恢复与重试

## 1. 错误分层

- **预期错误**（用户输入无效、资源不存在、业务规则违反）：
  正常流程的一部分，返回明确错误（4xx + 可读消息）。
- **意外错误**（bug、外部故障）：
  记录详细日志（含堆栈），对外返回通用消息（500，不泄露内部细节）。

## 2. 类型化错误

- 定义错误类型/码（领域错误码 + HTTP 映射）。
- 统一错误响应格式：

```json
{ "error": { "code": "VALIDATION_ERROR", "message": "邮箱格式不正确", "details": [...] } }
```

- 错误携带足够上下文（字段/规则/可修复建议），让调用者能行动。

## 3. 优雅失败（graceful degradation）

- **降级**：主路径失败 → 降级路径（缓存/默认值/只读模式）。
- **超时与重试**：外部调用设超时；重试带退避 + 上限（参考 microservices 韧性）。
- **熔断**：连续失败 → 快速失败（保护下游）。
- **不静默吞错**：catch 后要么处理要么抛出，不留"假装成功"。

## 4. 错误可观测性

- 错误日志：级别正确（error/warn），含请求上下文（request_id）。
- 指标：错误率、错误类型分布（参考 observability）。
- 告警：关键错误路径有告警（参考 slo）。
- **不记录敏感信息**：堆栈/参数脱敏。

## 5. 恢复策略

- 可重试错误（瞬时）：记录 + 重试队列/定时补偿。
- 不可重试（逻辑错）：报错 + 人工介入路径。
- 数据一致：失败的操作要有补偿/幂等（参考 db-migration/microservices）。

## 自查清单

- [ ] 预期/意外错误分层明确
- [ ] 错误类型化 + 统一格式
- [ ] 外部调用有超时/重试/熔断
- [ ] 无静默吞错
- [ ] 错误日志含上下文、无敏感信息
- [ ] 关键错误有指标与告警

## 边界

- 具体语言异常机制（exception/result/error 类型）按语言习惯。
- 与 tdd 配合：错误路径也要测试（边界/异常输入）。
