# Writing Shape — 写作塑形

把原始素材塑形为独立文章：这是**开采**（exploit）——探索已完成、
素材堆已定：承诺一个结构，挖素材填它。素材文件只读不改。

## 循环

1. **读素材堆**：完整读输入文件，形成整体印象
2. **确立先决条件**：与用户定下读者走进来时已**奠基**的概念；
   其他一切必须由某个块先奠基，后面的块才能依赖
3. **起草 2-3 个候选开头**：每个暗示不同论点/角度；全展示，
   逼用户选或合成混合体。选定的开头定义文章其余部分要做什么
4. **逐段生长**：开头落地后问"给定这个开头，读者下一步需要听什么？"
   从素材堆取料回答。下一块只能依赖已奠基概念，落地时奠基新概念。
   争论下一块的形式（段落/列表/表格/引文/代码块）——每个格式选择
   都有意且可辩护
5. **边写边追加**：不批量。每段/每块议定立即写入，让用户看到文章成形
6. **循环第 4 步直到完成**：用户决定何时完成

## 奠基（Grounding）

每个**概念**在被块依赖前必须**奠基**：读者要么进门就知道，
要么在更早的块里遇过。抓未奠基概念的块会失去读者。
单位是概念不是词：无术语也能依赖读者缺的想法；
有名字（**术语**）的概念，奠基 = 想法与术语一起落地。

两种奠基方式：
- **先决条件**：开头前已奠基，读者自带，开头时固定
- **引入**：某块确立，之后整篇文章都奠基

维护已奠基清单。问"下一步听什么"时，下一步需要的未奠基概念
本身就是答案：先奠基它（此处或更早的块），否则动不了。

**杠杆**：什么做先决条件 vs 文内奠基。开头要太多把读者关门外；
文内奠基太多开头淹死在定义里——确立先决条件时与用户商定。

## 自查清单

- [ ] 素材堆完整读过、素材文件只读
- [ ] 先决条件与用户商定
- [ ] 2-3 个候选开头展示并选定
- [ ] 每块只依赖已奠基概念、落地时奠基新概念
- [ ] 格式选择有意可辩护
- [ ] 边写边追加、用户决定完成

## 边界

- 塑形是"开采"模式：素材未探索完先做探索（explore），别硬塑形。
- 奠基清单是核心杠杆：无它，文章结构全靠感觉。
