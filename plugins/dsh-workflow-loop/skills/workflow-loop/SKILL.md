# Workflow Loop — 可委托工作流设计

**循环（loop）** = 用户生活中的重复模式：职业生涯、一周、一个早晨、
单个重复活动。把生活看作层层循环，能看出活动有多可预测——
可预测正是**值得委托**的原因。

## 何时用

- 设计可委托的重复工作流
- 自动化日常循环
- 把流程规格化（workflow spec）
- 找出用户没注意到的可委托循环

## 1. 词汇（规格需要时才用，非清单）

- **Trigger（触发）**：每次运行被什么点燃——**事件**（新邮件/新 issue）
  或**计划**（每天早晨）。事件触发通常更高效
- **Checkpoint（检查点）**：人在环中的点，被请去验证/决策。
  有的工作流无检查点全自动；有的完全不用 AI
- **Push right（推送靠右）**：把检查点尽量推迟——先做最大量工作，
  人类只被问一次、问得晚、带着一切准备好的
- **Brief（简报）**：检查点呈现的内容——紧凑、可决策的摘要
  （产出了什么、为什么、指向资产本身的链接），绝不是原始输出。
  用户读简报，不读草稿；**审查速度至上**

## 2. 用循环视角找循环

- 盘问（grilling）纪律：一轮一轮问、每问附推荐答案
- 用循环视角找值得规格化的循环，并提出用户没注意的
- **规格完成标准**：实现者 agent 能不问任何问题就构建出来。
  还有问题存在就不算完成——盘问到那为止

## 3. 产出

- workflow 规格存 `workflows/*.md`（事实源）
- 一个循环一个 workflow 规格；规格是循环的静态定义，
  运行是它的实时实例化
- **不做结构性强制**：规格需要 AI/检查点/计划才写，
  盘问没证明需要就不写

## 4. 自查清单

- [ ] 用循环视角找出值得委托的重复模式
- [ ] 触发（事件/计划）明确
- [ ] 检查点推送靠右（人类一次、晚、备好）
- [ ] 简报决策就绪（非原始输出）
- [ ] 规格可实现者无需提问
- [ ] 无未证明必要的结构性强制

## 边界

- 本技能是"设计规格"，执行交给实现者/运行系统。
- 循环视角是发现工具：不硬套，用户没感知的循环要提议而非强加。
