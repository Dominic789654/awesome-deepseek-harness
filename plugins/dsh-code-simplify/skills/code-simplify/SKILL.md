# Code Simplify — 代码简化

简化代码不是"删掉功能"，是**去掉不必要的复杂度**，让正确行为更清晰。

## 何时用

- 代码"能跑但太绕"
- 有重复逻辑可合并
- 抽象过度（为不存在的未来做了泛化）
- review 反馈"太复杂/看不懂"
- 简化既有代码（保持行为不变）

**不用**：用户没要求时别主动重构（参考 karpathy 的"外科手术式改动"）。

## 简化检查清单

### 1. 删冗余
- 重复代码 → 提取（但只在第 2-3 次使用时，过早提取是另一种过度）。
- 死代码/无用分支/注释掉的代码 → 删。
- 多余的包装/中间变量 → 内联。

### 2. 降复杂度
- 深嵌套（if/循环 3+ 层）→ 提前 return / 提取函数。
- 长函数（> 30 行）→ 按职责拆分。
- 复杂的条件表达式 → 提取命名清晰的布尔变量/函数。
- 类继承深链 → 组合优先。

### 3. 去不必要的抽象
- 只有一个实现/一个调用点的接口 → 考虑直接实现。
- 参数化但没人用的"灵活性" → 硬编码。
- 过度分层（service/repository 层层转发）→ 合并。

### 4. 命名与结构
- 模糊命名（data/temp/thing）→ 描述性命名。
- 控制流拐弯 → 直白写法。
- 魔法数字/字符串 → 命名常量。

## 简化流程

1. **先理解**：完整读懂代码（含调用方），确认行为。
2. **列简化点**：按清单逐项找可简化处。
3. **小步简化**：一次改一处，保持行为不变（参考 incremental）。
4. **验证**：测试通过 + 行为不变（有测试先跑，无测试说明风险）。
5. **交付 diff**：说明每处为什么简化、行为如何保持不变。

## 简化 vs 破坏

| 简化（好） | 破坏（坏） |
|---|---|
| 去掉复杂度 | 去掉功能 |
| 行为不变 | 行为改变 |
| 更清晰 | 更"聪明"（难懂） |
| 减少代码 | 压缩到不可读 |

## 纪律

- 简化后代码必须**仍然可读**：一行超长"聪明"代码不是简化。
- 拿不准某处能不能简化 → 保留并说明，让用户决定。
- 简化不是炫耀技巧；目标是"下一个工程师 5 秒看懂"。

## 边界

- 与 ponytail-dev 互补：ponytail 管"能不写就不写"，本技能管"写了就简化"。
- 大范围重构先出计划（参考 planning），不一次改完。
