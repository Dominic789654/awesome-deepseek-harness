# Framework Migration — 框架迁移

把遗留前端迁到现代框架：先选策略，再增量推进，依赖与风险全程管理。

## 何时用

- AngularJS（1.x）迁到 Angular（2+）
- 运行混合 AngularJS/Angular 应用
- 现代化遗留 React 代码
- 大版本框架/依赖升级
- 迁移路由与依赖注入系统

## 1. 迁移策略选型

| 策略 | 做法 | 适合 |
|---|---|---|
| Big Bang 全量重写 | 整应用重写后一次性切换 | 小应用/绿地 |
| 增量混合 | AngularJS+Angular 并行，逐特性迁移（ngUpgrade 互操作） | 大应用/持续交付 |
| 垂直切片 | 一次完整迁一个特性，新特性用新框架 | 中型/特性边界清晰 |

**推荐**：大应用走增量混合——业务不中断，每步可回退。

## 2. AngularJS → Angular 要点

- **混合引导**：UpgradeModule 同时引导两代框架
- **指令 → 组件**：逐条转换（scope/link → input/output/生命周期）
- **DI 迁移**：$provide/$injector → Angular 注入器；服务逐步替换
- **路由迁移**：$routeProvider → Angular Router（ui-router 兼容层过渡）
- 每完成一个特性跑全量回归；新旧并存期保持单一代码路径

## 3. React 现代化

- 函数组件 + Hooks 替代类组件（渐进迁移，一次一个组件树）
- 数据获取统一 React Query/SWR；状态管理收敛（Context/Zustand）
- 移除遗留模式：componentWillReceiveProps → useEffect 等
- 类型化：TS 逐步覆盖；测试随迁（组件测试 + 集成）

## 4. 依赖升级

- **版本路径**：逐大版本升级（1→2→3），别跨版本跳（破坏性变更累积）
- 升级前：锁定当前行为（测试覆盖 + 基线）
- 升级中：用 codemod 自动化机械性变更；changelog 逐条核对破坏性项
- 升级后：全量回归 + 性能对比；灰度放量

## 5. 风险与纪律

- **并行可回退**：每个迁移步骤独立可回退（特性开关/双实现）
- 小步高频：频繁合并，避免巨型迁移分支
- 测试先行：迁移前补关键路径测试，作为行为契约
- 性能基线：迁移前后对比（LCP/包体积/交互延迟）

## 6. 自查清单

- [ ] 迁移策略按应用规模选型（增量优先）
- [ ] 混合模式引导与互操作就位
- [ ] 每特性迁移后全量回归
- [ ] 依赖按版本路径逐级升级 + codemod
- [ ] 关键路径测试先行作为契约
- [ ] 每步可回退、有性能基线对比

## 边界

- 框架版本差异大（Angular 版本/React 生态），按目标版本文档。
- 迁移是长期工程：先建行为契约（测试），再动代码。
