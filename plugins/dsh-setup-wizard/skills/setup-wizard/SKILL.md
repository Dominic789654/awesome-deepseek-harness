# Setup Wizard — 交互式设置向导

**向导** = 一个 bash 脚本，逐步带人类走完手动流程（手做繁琐、
每次向 AI 重讲也繁琐的流程）：打开每个 URL、说明点什么复制什么、
捕获值写到该在的地方（.env/GitHub secrets）、每阶段确认、
显示还剩几阶段。

## 何时用

- 开通基础设施（只能人工做的步骤）
- 设置凭据/CI 密钥（第三方后台）
- 走陌生的第三方仪表盘
- 一次性迁移/切换

**不适用**：agent 自己能做的步骤。

## 1. 划定流程

把人类必须做的每个手动步骤 + 沿途捕获的每个值都列出来。
先读仓库，别冷问：
- 设置类：`.env*`、README、docker-compose、框架配置、
  `.github/workflows/*`（每个 `secrets.*`/`vars.*` 引用都是一个
  向导要产出的值）
- 迁移类：当前状态、目标状态、之间的不可逆动作

然后给用户看有序阶段清单 + 每个产出的值，确认（可增删改序）。
**完成标准**：每阶段按序命名；每个捕获值知道 (a) 人类从哪拿
(b) 写到哪（.env/secret/两者/无处）(c) 是否密钥。

## 2. 映射每阶段的路径

写清人类的确切路径："仪表盘 → 开发者 → API keys → 显示测试密钥 →
复制"→ 填充哪个变量。**不知道当前 UI/确切命令就说明并问用户或查文档**，
绝不编造可能不存在的步骤。完成标准：每阶段都有陌生人可照做的
具体指示。

## 3. 编写向导

按依赖顺序一个阶段一个 `stage`。用库工具：
`stage`/`say`/`step`/`open_url`/`ask`/`ask_secret`/`write_env`/
`set_secret`/`set_var`/`pause`/`confirm`；`TOTAL_STAGES` = 阶段数。

纪律：先打开 URL 再要值；密钥用 `ask_secret`；每个持久化的值
`write_env`；只有 CI 真需要的才 `set_secret`；不可逆动作前 `confirm`。
每阶段清屏只显示当前步（别让人类需要的滚出视野）；一个阶段一个任务。

## 4. 验证与交接

- 试跑一遍（可先 dry-run），确认流程可走通
- 向导默认一次性：放 scratch/scripts、任务完成即删；
  只有用户想要可重复的设置路径才提交进仓库

## 5. 自查清单

- [ ] 读仓库划定所有人工步骤与捕获值
- [ ] 阶段清单经用户确认
- [ ] 每阶段路径具体可照做（无编造步骤）
- [ ] 先开 URL 再要值、密钥隐藏输入
- [ ] 值写到正确位置（env/secret）
- [ ] 不可逆动作前 confirm + 验证可走通

## 边界

- 向导是"人机协作"工具：只覆盖 agent 无法代替的步骤。
- UI 会变：地图路径时以当前实际界面为准，不确定就问。
