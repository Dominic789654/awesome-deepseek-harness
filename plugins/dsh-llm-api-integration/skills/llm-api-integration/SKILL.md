# LLM API Integration — LLM API 集成模式

构建 LLM 应用：选对调用面、流式、工具调用、缓存与迁移纪律。

## 何时用

- 用 LLM API 构建应用（agent/MCP/工具定义/多代理/RAG/LLM 评委）
- 生成/摘要/提取/分类/改写/对话
- 调试拒答/截断/流式/工具调用/token
- 模型选型/定价/限制/缓存

## 1. 调用面

- **官方 SDK**（项目语言）是默认
- **原始 HTTP**（curl/requests/fetch）只在用户明确要求 cURL/REST、
  项目是 shell/cURL、或语言无官方 SDK 时用
- **绝不混用**：别因为"更轻"就在 Python/TS 项目里用 requests/fetch
- 不用 OpenAI 兼容 shim 代替官方 SDK

## 2. 不凭记忆写 SDK 用法

- 函数名/类名/命名空间/方法签名/导入路径必须来自显式文档
  （SDK 官方文档/仓库）
- 文档不可得（网络受限）→ 按模式写 + 跑编译器迭代错误
  （静态类型语言 compile-fix 循环更快）

## 3. 默认

- **流式**：长输入/长输出/高 max_tokens 时默认流式（防请求超时）；
  用 `get_final_message()` 取完整响应
- **思考模式**：复杂任务开思考（新模型用 adaptive 类型，旧模型用
  budget_tokens——按模型版本）
- **工具调用**：工具定义清晰（名称/描述/参数 schema/输出）
- **缓存**：长系统提示/工具定义用提示缓存省成本

## 4. API 漂移验证

训练记忆可能过时——常见漂移点：思考参数形状、工具类型版本、
参数命名风格、凭据管理方式。**写代码前对照当前文档验证**。

## 5. 模型迁移与审计

- 迁移到新模型：确认范围 → 逐文件分类 → 按目标模型破坏性变更
  逐个修改 → 审计提示文本（为旧模型写的提示不会自己宣布过期）
- 提示词审计：扫描过时模式（为旧模型写的"cruft"），
  报告带 file:line/原因/置信度 + 建议 diff

## 6. 自查清单

- [ ] SDK/HTTP 选择正确且不混用
- [ ] SDK 用法来自文档（非记忆）
- [ ] 长请求默认流式
- [ ] 工具定义完整、缓存合理
- [ ] 漂移点对照当前文档验证
- [ ] 迁移含提示词审计

## 边界

- 具体提供商（Anthropic/OpenAI/DeepSeek 等）API 形状不同，
  按所选提供商文档执行本技能的方法论。
- 本技能是"集成模式"：提供商细节永远以官方文档为准。
