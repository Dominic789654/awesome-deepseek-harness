# Bash Scripting — Bash 脚本防御模式

写可靠、可调试、安全的 Bash 脚本。

## 1. 脚本头（防御基线）

```bash
#!/usr/bin/env bash
set -euo pipefail
```

- `-e`：命令失败即退出（不带着错误继续跑）。
- `-u`：未定义变量报错（防拼写错误变量）。
- `-o pipefail`：管道中任一命令失败即整体失败（防"最后一条成功就掩盖错误"）。
- 需要部分容错时：在特定命令后 `|| true` / `|| handle_error`。

## 2. 参数与输入校验

- 检查参数数量：`if [ $# -lt 2 ]; then usage; exit 1; fi`
- 校验输入（路径存在、文件类型、值合法）。
- 使用 `readonly`/`local` 声明常量与局部变量。
- 引号：**所有变量加双引号**（`"$var"`）防空格/通配符问题。

## 3. 错误处理

- 统一错误出口：`die() { echo "错误: $*" >&2; exit 1; }`
- 关键步骤失败要能定位：打印上下文（`echo "> 步骤 X"`）。
- 临时文件：`trap 'rm -f "$tmp"' EXIT` 清理（防残留）。

## 4. 可调试性

- `set -x`（调试时开启，追踪每条命令）。
- 输出信息到 stdout，错误到 stderr（`>&2`）。
- 日志带时间戳（长任务）。
- 不吞错误输出（除非有意，且说明原因）。

## 5. 安全注意

- 不把密钥硬编码；从环境变量/密钥文件读取。
- 路径带引号 + 不信任外部输入拼进命令（防注入）。
- 下载执行外部脚本前三思（供应链风险）。
- 权限最小化（脚本/产物 755 以内）。

## 6. 结构与风格

- 函数化：主逻辑拆函数（`main` 入口 + 小函数）。
- 命名清晰：变量/函数用 snake_case 描述性命名。
- 注释"为什么"（复杂逻辑），不重复代码本身。
- 一个脚本一件事；复杂系统用多个脚本 + 公共库。

## 边界

- 跨平台（macOS/Linux）注意差异（sed/awk/date 参数）。
- 复杂逻辑优先考虑用更安全的语言（Python），Bash 管"胶水"。
