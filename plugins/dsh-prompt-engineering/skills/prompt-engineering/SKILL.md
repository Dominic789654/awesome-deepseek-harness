# Prompt Engineering — 提示词工程模式

用高级提示词技术最大化 LLM 的性能、可靠性与可控性。

## 何时用

- 为生产 LLM 应用设计复杂提示词
- 优化提示词性能与一致性
- 实现结构化推理（CoT/ToT）
- 构建带动态示例选择的 few-shot
- 创建可复用提示词模板（变量插值）
- 调试提示词问题

## 1. 结构化推理模式

- **Chain-of-Thought（思维链）**：让模型先推理再回答（"一步步想"），
  复杂任务显著提升准确率。关键：要求**展示推理过程**再给结论。
- **Tree-of-Thought（思维树）**：多路径探索再择优（更复杂任务）。
- **结构化输出**：强制 JSON/固定格式（指定 schema，方便解析与校验）。
- **角色/约束**：明确角色、规则、边界（"你是一个…只基于…回答"）。

## 2. Few-shot 模式

- 给 2-5 个高质量示例（输入→输出），让模型学会格式与风格。
- **动态示例选择**：按查询相似度选最相关的示例（而非固定几个）。
- 示例要覆盖典型 + 边界情况；示例质量 > 数量。

## 3. 模板与变量

- 可复用模板：占位符插值（`{context}`、`{query}`），不硬编码。
- 变量插值要转义/校验（防注入，参考 security-hardening）。
- 版本化：prompt 是代码，入库、可回滚（参考 git-workflow）。

## 4. 优化与调试

- **迭代优化**：基线评估 → 改一版 → 对比（参考 llm-eval）。
- **错误分析**：失败案例分类（格式错/幻觉/答非所问）→ 针对性改。
- **最小修改**：一次只改一处（变量/示例/指令），知道哪个生效。
- **防幻觉指令**：强约束"不知道就说不知道，不编造"。

## 生产提示词自查

- [ ] 指令明确无歧义（模型能复述任务）
- [ ] 有约束/边界（范围、格式、禁止项）
- [ ] few-shot 示例质量高且覆盖边界
- [ ] 输出格式结构化（便于解析）
- [ ] 有版本管理与回滚
- [ ] 有评估与回归（参考 llm-eval）

## 边界

- 提示词是工程不是魔法：结构（检索/编排/校验）往往比措辞更重要。
- 与 rag/llm-eval 配合：检索增强上下文、评估驱动优化。
