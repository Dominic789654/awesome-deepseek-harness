# Reverse Engineering — 逆向工程

读懂编译产物：二进制分析、控制流重建、内存取证、协议逆向。

## 何时用

- 逆向未知可执行文件以理解其行为
- 恶意软件/混淆二进制分析（Ghidra / IDA Pro / Binary Ninja）
- 从编译代码重建高层控制流
- 识别编译器引入模式（栈 canary、PIC trampoline）
- 内存取证与协议逆向

## 1. 二进制分析模式

**反汇编基础**：先静态（strings/导入表/节区）→ 再反汇编 → 反编译。

**控制流模式识别**：
- 条件分支：`cmp` + `jne/jge/jae`（区分有符号/无符号比较）
- 循环：`xor ecx,ecx` 初始化 → `cmp` 条件 → `inc/jmp`（for/while 特征）
- switch 表：跳转表（jump table）识别
- vtable 分发：虚函数调用特征

**工具**：Ghidra（免费）/ IDA Pro / Binary Ninja；先用 strings 与
节区信息缩小范围，再逐函数分析。

## 2. 内存取证

- 内存镜像分析（Volatility 类工具）：进程列表、网络连接、注入模块
- 定位隐藏/解压到内存的代码（进程注入、打包器）
- 时间线重建：文件访问/进程启动/网络活动顺序
- 取证链：镜像哈希校验、记录工具与命令、证据完整性

## 3. 协议逆向

- 抓包（Wireshark/tcpdump）→ 识别帧结构与字段
- 定位长度字段/校验/加密起始点
- 二分法验证字段语义（改字段观察行为变化）
- 未知加密：先找密钥交换与初始化向量，再试已知算法

## 4. 反逆向对抗（理解防御侧）

- 混淆：控制流平坦化、字符串加密、反调试检测
- 壳/打包器：入口点混淆、运行时解压
- 完整性校验：校验自身哈希防补丁
- 对抗思路：先识别防御手段再决定投入（脱壳→静态→动态）

## 5. 合规与边界

- 只逆向你有权分析的软件（自有/授权/开源/研究样本）
- 恶意软件分析在隔离环境（VM/沙箱），断网
- 结果与证据记录完整（可复现、可追溯）

## 6. 自查清单

- [ ] 静态信息（strings/导入/节区）先行
- [ ] 控制流模式已识别（分支/循环/switch/vtable）
- [ ] 内存取证有证据链（哈希/工具记录）
- [ ] 协议字段语义有验证（非猜测）
- [ ] 隔离环境分析、无网络泄漏
- [ ] 分析对象有合法授权

## 边界

- 逆向耗时且依赖经验：先定目标（行为？算法？漏洞？）再投入。
- 工具链重（Ghidra/IDA），按平台与样本类型选。
