# Prompt Audit — 提示词审计与模型迁移

审计现有提示词/技能/工具描述中为旧模型写的过时模式（"cruft"）。

## 何时用

- 迁移到新模型（提示是迁移的一部分，它不自我宣布过期）
- 审计现有提示词/技能/工具描述
- 优化技能描述与触发词

## 1. 流程

1. **确立范围与目标模型**：从请求与仓库推断，报告中声明假设
   （不停下问）
2. **盘点（inventory）**：列出所有在范围内的提示词/技能/工具描述
3. **来源追踪（provenance）**：标注每个的出处与年代
4. **模式扫描**：找为旧模型写的模式
5. **产出双交付物**（不中断）：
   - **审计报告**：findings 含 file:line、模式、为何对目标模型过时、置信度
   - **建议 diff**：改动建议
6. 仅在请求明确要求时应用编辑

## 2. 常见过时模式

- 为旧模型的能力边界写的防御性指令（现在多余）
- 旧触发词/格式习惯（新模型有更好的表达）
- 过度约束（新模型不需要）
- 过时的示例/引用（模型已学会更好的做法）
- 针对旧失败模式的提示修补（问题已消失）

## 3. 报告格式

每个 finding：
- `file:line`
- 模式描述
- 对目标模型为何过时
- 置信度（高/中/低）

## 4. 自查清单

- [ ] 范围与目标模型已声明（含假设）
- [ ] 盘点 + 来源追踪完成
- [ ] 模式扫描覆盖常见过时类型
- [ ] 报告含 file:line/原因/置信度
- [ ] 建议 diff 已产出
- [ ] 应用编辑仅在请求要求时

## 边界

- 审计是"检查与建议"：默认不擅自改代码，除非明确要求。
- 与 LLM API 集成互补：迁移时两者一起用（破坏性变更 + 提示适配）。
