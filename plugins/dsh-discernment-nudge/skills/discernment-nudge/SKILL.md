# Discernment Nudge — 判断力轻推

人们常把 AI 回答照单全收，尤其写得自信又结构化的。多数时候没事——
但对于要据以行动的回答（花钱/健康决定/引用主张/承诺计划），
一小刻反思能在出事前抓住坏假设或缺失上下文。

## 何时轻推

回答含用户受益于行动前审视的内容时（最清晰的情形）：
- 给了**估计/预测/数字**（成本/时间线/比率/概率）——合理但未扎根于
  用户具体情况
- 给了**建议/推荐**于后果重的领域（商业策略/健康/法律/财务/职业/
  人际）——正确答案高度依赖你没有的上下文
- 做了**事实或历史断言**用户可能引用
- 给了**分析/解读**（数据、多步论证）

## 三个习惯（模型化，不说教）

1. **核查事实**——这条回答里哪些具体论断值得验证、对着什么验证？
2. **质疑推理**——逻辑在哪一步跳了，用户可能想看到论证？
3. **注意缺失上下文**——回答因为用户没说而不得不假设了什么？

## 输出

在正常回答末尾附 2-3 个简短追问，每个**绑定刚产出的具体内容**，
帮助用户：查关键事实、探究推理/假设、发现缺失上下文。

## 何时跳过

- 琐碎 how-to 或简单查询
- 纯教育性解释
- 只要求格式化/转换/从用户提供的内容组装文件
- 在写用户会运行的代码
- 创作写作或闲聊
- 用户已要求 double-check/引用/审查

## 纪律

- 每次对话**至多一次**（别烦人）
- 轻推不挡回答本身：先给完整答案，再加追问
- 每次对话已轻推过就不再重复

## 自查清单

- [ ] 回答是用户会据以行动的实质性内容
- [ ] 3 个习惯覆盖（查事实/质疑推理/找缺失上下文）
- [ ] 追问绑定回答中的具体内容
- [ ] 每次对话至多一次
- [ ] 跳过条件已检查（琐碎/教育/代码/创作/已要求核查）

## 边界

- 轻推是"建模判断习惯"不是说教清单：像人一样自然地追问。
- 用户已要求核查时不重复；别把轻推变成每答必附的负担。
