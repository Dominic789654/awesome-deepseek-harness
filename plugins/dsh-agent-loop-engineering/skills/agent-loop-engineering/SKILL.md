# Agent Loop Engineering — Agent 循环工程

设计"提示并编排 agent"的循环系统：循环是运行中反复执行的工作流实例。

## 何时用

- 搭建自主 agent 循环（自动处理日常任务）
- 设计多循环协调
- 审计循环的代价/质量/就绪度
- 初始化新循环（loop-init）

## 1. 循环分级

- **L1（自动 + 报告）**：无需人工干预运行；产出报告，人工审阅决定行动
- **L2（辅助）**：需要触发（手动或计划），部分步骤人工参与
- 每循环定义：节奏（cadence）、skill/starter、状态文件、阶段、交接点

## 2. 常用循环模式

- **Daily Triage**：每日自动化分类 + 报告，人工每周审阅 issue
- **PR Babysitter**：活跃时段 10-15 分钟辅助——worktree 建议修复，
  **验证器必需**、默认不自动合并
- **Dependency Sweeper**：6h-1d 节奏，只做 patch + 低风险 CVE
  （首 30 天），验证器 = 全量安装+测试，主版本升级走人工门
- **Changelog Drafter**：每日/发布前起草 changelog，人工批准后发布

## 3. 多循环协调

- 循环间交接点清晰（设计决策/大重构/新模式验收）
- 循环共享状态（STATE.md）与单一事实源
- 冲突避免：职责不重叠（谁拥有什么）

## 4. 验证器与人工门

- **每个会改变系统的循环必须有验证器**（测试/检查跑过才算数）
- 人工门：主版本/破坏性/发布类动作默认人工批准
- 低风险自动、高风险人工——边界写进循环定义

## 5. loop-audit 与反模式

- 审计：就绪评分（模式验证/采纳评分）、成本（token/时间）
- 反模式：无验证器的自动合并、无人工门的破坏性操作、
  循环漂移（节奏变了没人发现）、职责重叠冲突

## 6. 自查清单

- [ ] 循环分级明确（L1/L2）
- [ ] 节奏/状态/交接点已定义
- [ ] 验证器必需（改变系统必有）
- [ ] 人工门就位（主版本/发布/破坏性）
- [ ] 多循环职责不重叠
- [ ] 定期 loop-audit（就绪/成本）

## 边界

- 与可委托工作流设计互补：那是"要不要委托"，本技能是"循环系统怎么工程化"。
- 循环要自我吞噬（dogfood）：先用在自己的仓库，验证再推广。
