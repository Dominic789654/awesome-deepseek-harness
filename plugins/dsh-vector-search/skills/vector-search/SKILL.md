# Vector Search — 向量检索工程

选对 embedding、切好块、调好索引、必要时混合关键词：系统化构建语义检索。

## 何时用

- 为 RAG/语义搜索选 embedding 模型
- 优化分块策略
- 调优向量索引（召回/延迟/成本）
- 混合检索提升召回（精确匹配 + 语义）
- 领域/多语言内容检索

## 1. Embedding 模型选型（2026 参考）

| 模型 | 维度 | 最大 token | 适合 |
|---|---|---|---|
| voyage-3-large | 1024 | 32000 | Claude 应用（Anthropic 推荐） |
| voyage-code-3 | 1024 | 32000 | 代码搜索 |
| text-embedding-3-large | 3072 | 8191 | OpenAI 高精度 |
| bge-large-en-v1.5 | 1024 | 512 | 开源本地部署 |
| multilingual-e5-large | 1024 | 512 | 多语言 |

选型原则：代码 vs 散文 vs 多语言按场景匹配；**不要混用 embedding 模型**
（向量空间不兼容）。

## 2. Embedding 流水线

```
文档 → 分块（重叠/尺寸）→ 预处理（清洗/归一化）→ Embedding → 向量
```

- **分块要保语义边界**：别过碎丢上下文，别过大超 token 限制被截断
- 预处理：清洗噪声、归一化（余弦相似度检索需要）
- 批量请求 + 缓存静态内容（避免重复计算）
- **元数据必存**：过滤与调试靠它

## 3. 向量索引调优

- 索引类型（HNSW/IVF/平坦）：按数据量与召回-延迟权衡选
- 参数：HNSW 的 M/efConstruction、IVF 的 nlist/nprobe
- 维度压缩（降维/量化）在精度与成本间权衡
- 评测：用真实查询集测召回@k，别只信默认配置

## 4. 混合检索（向量 + 关键词）

```
查询 → 向量检索 → 候选 ─┐
      关键词检索 → 候选 ─┴→ 融合 → 结果
```

- **关键词不可省**：精确匹配（名称/代码/领域词）向量常漏
- 融合方法：**RRF**（互惠排名融合，通用首选，免调参）/
  Linear（加权和，可调平衡）/ **Cross-encoder 重排**（质量最高）/
  Cascade（先过滤再重排，效率）
- 权重在**你自己的数据上实测调**；记录两种分数便于调试；A/B 测真实影响

## 5. 自查清单

- [ ] embedding 模型按场景选型且全库统一
- [ ] 分块保语义边界，元数据完整
- [ ] 索引参数按真实查询集评测过
- [ ] 混合检索已启用（关键词 + 向量）
- [ ] 重排序（如需要）已接入
- [ ] 召回与延迟在真实数据上验证

## 边界

- 模型市场变化快，选型前查最新基准；API 成本与本地部署权衡。
- 检索质量最终以端到端 RAG 效果为准，别只优化单环节指标。
