# Signed Audit Trails — Agent 工具调用签名审计

给每一个 agent 工具调用（Bash/Edit/Write/WebFetch 等）加密码学审计：
策略评估先行 + 签名收据落盘 + 任何人可离线验证。

## 何时用

- **受监管环境**（金融/医疗/关键基础设施）：需要 agent 行为的防篡改证据
- **CI/CD 流水线**：证明每个构建步骤都过了策略门
- **多方协作**：对手方要验证你的 agent 行为，但不想信任你的运维
- **合规场景**（欧盟 AI 法案第 12 条、SLSA 来源证明）：普通日志不够

## 1. 机制

1. **策略先行**：每次工具调用先按策略（如 Cedar）评估，拒绝则工具不执行。
2. **签名收据**：执行后生成 Ed25519 签名收据——JCS 规范化、
   **哈希链**（每条收据链到上一条）、含输入/策略/结果。
3. **离线验证**：任何人持公钥一条命令验证整条链
   （`npx @veritasacta/verify receipts/*.json`）——无网络、无厂商、无需信任操作者。

## 2. 关键配置（通用形态）

- 钩子：PreToolUse（策略评估，拒绝即 `exit 2` 阻断）；
  PostToolUse（签名收据写入 `./receipts/`）。
- 私钥：首次运行生成；**只提交公钥指纹**（收据 `public_key` 字段），
  私钥与 receipts 目录进 .gitignore。

## 3. 策略编写（Cedar 示例）

```
permit(principal, action in [Action::"Read","Action::"Glob","Grep","WebSearch"], resource);   // 默认放行只读
permit(principal, action == Action::"Bash", resource) when { context.command_pattern in ["git","npm","ls","cat","node"...] };  // Bash 白名单
// 其余默认拒绝（deny 权威）
```

原则：**默认拒绝，最小放行**；按工具/命令/路径分级授权。

## 4. 审计链与验证

- 收据含：调用输入、决策结果、所用策略、签名、时间戳、前一收据哈希
- 验证：公钥验签 → 链完整性（哈希连续）→ 策略合规性
- 防篡改：任何中间修改都会破坏链，审计方可立即发现

## 5. 与 CI/CD 集成

- 流水线每步（构建/发布）都产生签名收据 → 发布来源可证明（SLSA 对齐）
- 收据归档到不可变存储，定期抽样离线验证
- 审计报告：链完整 + 所有拒绝事件都有记录

## 6. 自查清单

- [ ] 策略默认拒绝、按工具分级放行
- [ ] 每条工具调用有签名收据（含策略/结果/时间戳）
- [ ] 收据哈希链连续、可离线验证
- [ ] 私钥不落库、公钥指纹已提交
- [ ] CI/CD 每步策略门 + 收据归档
- [ ] 定期抽样验证链完整性

## 边界

- 签名审计是"证据层"不是"安全层"：策略要写对，密钥要管好。
- 具体实现（protect-mcp 等）按项目选；先小范围试点再全量。
