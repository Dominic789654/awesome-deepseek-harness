# Shipping — 发布上线

把变更安全地送到用户手里。发布不是"点一下部署"——是**检查、灰度、回滚、
监控**的完整流程。

## 何时用

- 准备发布新版本/功能
- 部署到生产
- 发版前检查
- 上线后验证

## 发布前检查清单

### 代码与质量
- [ ] CI 全绿（lint/类型/单测/构建/集成）
- [ ] 代码评审通过（参考 code-review 技能）
- [ ] 关键路径有测试覆盖（参考 tdd 技能）
- [ ] 无调试残留、无 TODO 阻塞项

### 数据与兼容
- [ ] 数据迁移已执行/可回滚
- [ ] 前后端兼容（API 版本、字段兼容）
- [ ] 外部依赖（第三方 API）变化已确认

### 发布计划
- [ ] 发布窗口确定（低峰期）
- [ ] 回滚预案写清楚（触发条件 + 操作步骤）
- [ ] 负责人与通知对象确定
- [ ] 上线后监控项明确（指标/日志/告警）

## 发布执行

### 灰度策略

- **小步走**：先小比例（如 5-10% 流量/用户），观察后再放大。
- **金丝雀**：先给内部/少量真实用户，验证核心路径。
- **分阶段**：功能开关（feature flag）逐步放开。
- 每阶段确认无异常再推进；异常立即停止放量。

### 回滚优先

- 出问题**先回滚再调查**，不在生产上现场调试。
- 回滚要快（< 15 分钟），预案里写清具体操作。
- 回滚后保留现场（日志/快照）供调查。

## 上线后监控

- **立即检查**（发布后 15 分钟）：
  - 核心指标（可用性/错误率/延迟）vs 基线（参考 slo/observability）。
  - 关键日志无新错误。
  - 用户可走通核心流程。
- **持续观察**（24-48h）：趋势、慢增长问题、告警响应。
- 异常响应：按 runbook 执行（参考 runbook 技能）。

## 发布报告模板

```markdown
## 发布记录：<版本/变更>

- **时间**：…
- **范围**：…
- **灰度计划**：…
- **回滚预案**：…
- **监控项**：…
- **结果**：✅ 成功 / ⚠️ 有惊无险 / ❌ 回滚
```

## 边界

- 涉及生产部署的具体操作需用户确认/授权。
- 关键业务发布（支付/数据）按团队流程，本技能提供通用框架。
