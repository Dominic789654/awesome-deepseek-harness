# LLM Finetuning — LLM 微调路由与配方

先决定"要不要微调、用哪种方法"，再谈训练配方：评估先行，出口优先。

## 何时用

- 启动任何微调项目（选定框架/基座前先读本技能）
- 不确定 RAG/提示词工程是否更省
- 在偏好优化（DPO 系）与强化方法（GRPO/RLVR）间选择
- 提交训练前估算模型/方法组合规模

## 1. 出口优先（Off-Ramps First）

多数"帮我微调"的诉求用别的方式更便宜更好：

- **事实易变**（价格/文档/时事）→ **RAG**：微调烤进快照，易变事实立刻过期。
- **行为未定**（目标行为还在摸索/逐请求变化）→ **提示词工程**：别锁定未稳定的行为。
- **稳定密集的领域知识** → 按文本量路由：

| 领域文本量 | 路由 |
|---|---|
| <10MB | 仅 RAG |
| 10MB–500MB | RAG + 微调 |
| 500MB–10GB | CPT（继续预训练）后 SFT |
| >10GB | 必须 CPT |

CPT 学习率 ≈ 预训练 LR 的 **10%**。

## 2. 方法路由表

| 情况 | 方法 |
|---|---|
| 事实频繁变 | RAG，不微调 |
| 行为还在摸索 | 提示词工程 |
| 稳定领域知识 ≥500MB | CPT → SFT |
| 有输入/输出样例 | SFT（LoRA/QLoRA） |
| 有偏好对或 👍/👎 | DPO/ORPO/KTO |
| 有可验证的 pass/fail 信号 | GRPO+RLVR |
| 还没有 eval harness | 停下，先建评估 |

偏好对 → DPO（长度偏差用 SimPO，内存受限用 ORPO）；非配对 👍/👎 → KTO。
可验证成功信号 → RLVR + GRPO（按失败模式选 DAPO/GSPO/Dr.GRPO）。

**在这一切之前：评估设施必须先存在。**

## 3. LoRA/QLoRA 配方要点

- LoRA：只训练低秩适配器，参数极小；α=2r 常见（all-linear 目标模块）
- QLoRA：4-bit 量化基座 + LoRA，单卡可微调更大模型
- 数据质量 > 数量：清洗、去重、格式一致
- 训练中持续用 eval 集监控，防过拟合/灾难性遗忘

## 4. 评估先行（Eval Harness First）

- 微调前先建 eval：任务集 + 指标 + 基线（基座模型得分）
- 每次实验同口径对比：方法/数据/LR 变更前后必须可量化
- 防回归：关键能力集加入持续评估
- 没有评估就跑训练 = 盲飞

## 5. 量化导出

- FP8（Hopper+）/ NVFP4（Blackwell 代）/ AWQ（旧卡）/ GGUF+imatrix（边缘端）
- 导出后跑一轮 eval 验证质量损失可接受

## 6. 自查清单

- [ ] 已排除 RAG/提示词出口（或明确叠加）
- [ ] 方法按数据形态选型（SFT/DPO/KTO/GRPO）
- [ ] eval harness 先于训练存在，有基线
- [ ] LoRA/QLoRA 配方参数明确（α=2r、目标模块）
- [ ] 训练中持续评估防过拟合
- [ ] 导出量化后验证质量

## 边界

- 微调烧钱：先小规模试点 + 评估验证价值，再放大。
- 各框架（HF TRL/axolotl 等）实现细节不同，按所选框架查文档。
