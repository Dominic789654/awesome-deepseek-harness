# Security Hardening — 安全加固

把每个外部输入当敌人、每个密钥当圣物、每次授权检查当必做。安全不是一个
阶段——它是每一行触及用户数据、鉴权或外部系统的代码上的约束。

## 何时用

- 构建任何接收用户输入的功能
- 实现鉴权/授权
- 存储或传输敏感数据
- 集成外部 API/服务
- 添加文件上传、webhook、回调
- 处理支付或 PII 数据
- **处理 LLM 输出**（提示注入面）

## 第一步：威胁建模（先建模再加固）

没有威胁模型的加固是瞎猜。动手前花五分钟像攻击者一样思考：

1. **画出信任边界**：不可信数据从哪里进入系统？HTTP 请求、表单、文件上传、
   webhook、第三方 API、消息队列，以及 **LLM 输出**。每个边界都是攻击面。
2. **列出资产**：什么值得偷/破坏？凭据、PII、支付数据、管理员操作、资金流动。
3. **对每个边界跑 STRIDE**：

| 威胁 | 提问 | 典型缓解 |
|---|---|---|
| Spoofing 伪装 | 能冒充用户/服务吗？ | 鉴权、签名验证 |
| Tampering 篡改 | 数据能被改动吗？ | 完整性校验、参数化查询、HTTPS |
| Repudiation 抵赖 | 动作能被否认吗？ | 安全事件审计日志 |
| Information disclosure 泄露 | 数据会泄漏吗？ | 加密、字段白名单、通用错误信息 |
| Denial of service 拒绝服务 | 能被压垮吗？ | 限流、输入大小上限、超时 |
| Elevation of privilege 提权 | 能获得不该有的权限吗？ | 授权检查、最小权限 |

4. **用例旁边写滥用用例**：对每个功能问"我怎么滥用它？"——那将成为你的
   第一个测试。

如果你说不出一个功能的信任边界，你还没准备好保护它。

## 三层边界系统

### 永远做（无例外）

- 在系统边界校验所有外部输入（API 路由、表单处理器）
- **所有数据库查询参数化**——绝不把用户输入拼进 SQL
- 输出编码防 XSS（用框架自动转义，不绕过）
- 所有外部通信走 HTTPS
- 密码用 bcrypt/scrypt/argon2 哈希（绝不存明文）
- 设置安全头（CSP、HSTS、X-Frame-Options、X-Content-Type-Options）
- 会话 cookie 用 httpOnly、secure、sameSite
- 每次发布前对锁文件跑包管理器原生 audit

### 先问人（需人工批准）

- 新增鉴权流程或改鉴权逻辑
- 存储新类别的敏感数据（PII、支付信息）
- 新增外部服务集成
- 修改 CORS 配置
- 绕过任何"永远做"的安全措施

### 审查必做（实现中自查）

- 上传文件：类型白名单 + 大小限制 + 不信任文件名 + 隔离存储
- 日志：不记录密钥/PII/完整请求体
- 错误信息：对外统一通用提示，细节进内部日志
- LLM 输出：渲染前按 HTML 转义；不把模型输出拼进 SQL/命令
- 依赖：锁定版本，发布前 audit

## 交付时输出

- 威胁建模结果（信任边界 + 资产 + STRIDE 表）
- 已应用的"永远做"清单
- 需人工批准项的清单（明确列出，不擅自做）
- 已知残留风险说明

## 边界

- 本技能提供开发期安全纪律，不替代专业渗透测试/合规审计。
- 涉及具体合规（GDPR/CCPA/等保）时说明需专业评估。
