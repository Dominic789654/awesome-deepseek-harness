# RAG — 检索增强生成

构建基于外部知识源的 LLM 应用：检索相关文档 → 生成有依据的回答，减少幻觉。

## 何时用

- 私有文档问答系统
- 带当前/事实信息的聊天机器人
- 自然语言语义搜索
- 用有依据的回答减少幻觉
- 让 LLM 访问领域知识
- 文档助手、带来源引用的研究工具

## RAG 核心组件

### 1. 向量数据库

- **用途**：高效存储与检索文档嵌入。
- 选型：按规模/成本/部署方式（开源 Qdrant/Milvus/Chroma vs 托管）。
- 索引：HNSW/IVF；权衡召回率与延迟。

### 2. 文档处理管线

1. **清洗**：去噪、格式统一、去重。
2. **分块**：按语义/结构切块（标题、段落、固定大小+重叠）。
   - 块太小丢上下文，太大稀释相关度；常见 300-800 token + 重叠。
3. **嵌入**：选嵌入模型（维度/成本/语言适配）。
4. **入库**：块 + 元数据（来源/章节/时间）一起存，便于引用与过滤。

### 3. 检索与生成

- **检索**：查询嵌入 → 向量相似度 Top-K（可加关键词混合与元数据过滤）。
- **重排**（可选）：对 Top-K 用交叉编码器重排，提升精度。
- **生成**：把检索到的块拼进 prompt（带来源标记），LLM 只基于上下文回答。
- **引用**：回答引用来源块（来源可追溯是 RAG 的核心价值）。

## 常见问题与对策

| 问题 | 对策 |
|---|---|
| 检索不到相关内容 | 调块大小/重叠、加混合检索、检查嵌入模型 |
| 检索到但答不对 | 加重排、改进 prompt 指令 |
| 幻觉（答了不在上下文的内容） | 强指令"只基于上下文"、检测无依据回答 |
| 延迟高 | 降 K、索引优化、缓存查询 |
| 数据更新不生效 | 增量入库、版本管理 |

## 评估

- 检索质量：召回率/命中率（ground-truth 测试集）。
- 生成质量：忠实度（是否基于检索内容）、相关性、引用正确性
  （参考 llm-eval 技能）。

## 输出

- RAG 方案：数据管线 + 向量库选型 + 检索策略 + 评估计划。
- 实现时给出关键代码/配置与理由。

## 边界

- 嵌入/向量库选型按项目预算与规模；本技能提供框架。
- RAG 不解决所有幻觉：敏感场景仍需人工审核。
