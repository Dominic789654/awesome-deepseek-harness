# Distributed Debugging — 分布式系统排障

快速应急响应 + 现代可观测性：日志、追踪、指标三件套定位根因。

## 何时用

- 生产故障应急响应
- 系统性能问题（CPU/内存/IO/网络）
- K8s 异常（Pod 崩溃/OOM/网络/存储）
- 微服务通信与依赖问题
- 消息队列积压/死信
- 根因分析

## 1. 应急响应流程

1. **止血优先**：先恢复服务（回滚/隔离/扩容），再查根因
2. **建立时间线**：变更窗口 + 告警触发 + 用户影响
3. **数据收集**：指标异常 → 日志报错 → trace 慢链路（三层联动）
4. **假设验证**：一次验证一个假设，别乱试
5. **根因确认**：修复后监控确认，写复盘

## 2. 可观测性三件套

- **日志**：ELK/Loki 类；按 trace-id/请求 id 关联；先看错误级别再下钻
- **指标**：Prometheus 类；RED（服务）/ USE（资源）方法快速定位层
- **追踪**：Jaeger 类；跨服务链路定位慢节点（延迟突增服务）

## 3. K8s 排障

- Pod 状态异常：`kubectl describe pod` / `kubectl logs -f` / events
- OOMKilled：看 limit 与内存曲线；CPU 节流：看 throttling
- 网络：Service/DNS/CNI 分层排查（`kubectl exec` + dig/curl）
- 存储：PV/PVC 状态、存储类、容量耗尽
- Init 容器/sidecar 失败：先看 init 容器日志

## 4. 网络与 DNS

- 抓包：tcpdump/Wireshark；延迟分析（eBPF 工具）
- DNS：dig/nslookup；服务发现问题（K8s CoreDNS）
- 负载均衡/防火墙/安全组误配置排查
- 服务网格：路由/熔断/重试策略问题

## 5. 性能与微服务

- 系统性能：CPU/内存/磁盘 IO/网络利用率分析
- 应用画像：内存泄漏、CPU 热点、GC 问题
- 数据库：慢查询、连接池、死锁
- 缓存：Redis 命中率/键过期/大键
- 微服务：依赖调用失败/超时/熔断；消息队列消费滞后与死信

## 6. 自查清单

- [ ] 先止血再查因（时间线已建）
- [ ] 指标/日志/追踪三件套联动
- [ ] 一次验证一个假设
- [ ] K8s 问题按 describe/logs/events 流程
- [ ] 网络按层排查（DNS→连通→策略）
- [ ] 根因确认 + 监控 + 复盘记录

## 边界

- 生产排障先沟通影响面再操作（变更需审批时走流程）。
- 工具栈按团队（Datadog/ELK/Prometheus 等），方法论通用。
