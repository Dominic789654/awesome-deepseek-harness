# Wayfinder — 大工程决策地图

模糊的大想法超出单个会话，且被迷雾包裹：从**这里**到**目的地**的路
还看不见。Wayfinding 是找路，不是冲向目的地——把路画成 issue 跟踪器
上的**共享地图**，然后逐个解析它的**决策票据**（解析结果是决策，
不是待执行的构建切片），直到路径清晰。

## 1. 命名目的地（第一件事）

目的地因工程而异，命名它塑造每张票据：可能是要交接迭代的规格、
规划前要锁定的决策、或就地完成的变更（如数据结构迁移）。
地图与领域无关：工程工作、课程内容，什么形态都行。

## 2. 规划，不执行

- 默认**只规划**：每张票据解析一个决策；地图完成 = 路径清晰、
  动手前再无决策待定
- "干脆直接做"的冲动通常是到达地图边缘的信号——该交接了
- 工程可在 Notes 里覆盖此默认（把执行带进地图），否则只产决策不产交付物

## 3. 按名字引用

- 每张地图与票据都是 issue，有**名字**（标题）
- 人类读到的所有东西（叙述/Decisions-so-far）用名字引用，
  绝不用裸 id/编号/slug——`#42, #43` 的墙不可读，名字一眼可读

## 4. 地图

地图是跟踪器上的单个 issue（标 `wayfinder:map`），票据是它的子 issue。
地图是**索引不是存储**：列已做决策 + 指向持有细节的票据链接；
每个决策只在票据里存在一次，地图只摘要 + 链接。

**地图体**：
- Destination：到达终点什么样（1-2 行，每会话先定位再选票据）
- Notes：领域/每会话应 consult 的技能/偏好
- Decisions so far：每行一张已关票据（标题链接 + 一行摘要）

## 5. 自查清单

- [ ] 目的地已命名并写进地图
- [ ] 票据是"决策"型（非构建切片）
- [ ] 按名字引用（无裸编号墙）
- [ ] 地图是索引，细节只在票据
- [ ] 逐个解析票据直到路径清晰
- [ ] 路径清晰即交接（除非 Notes 覆盖）

## 边界

- 与执行类工作流互补：wayfinder 先解决"往哪走"，执行才谈纪律。
- 具体跟踪器操作（子 issue/阻塞/前沿查询）随平台实现。
