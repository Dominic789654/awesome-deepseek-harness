# Codebase Design — 代码库设计（深模块）

设计**深模块**：小接口背后藏大量行为，放在干净的接缝上，通过接口可测。
目标是调用方杠杆、维护者局部性、人人可测。

## 1. 术语（精确使用，勿替换）

- **Module（模块）**：有接口和实现的任何东西——函数/类/包/跨层切片
- **Interface（接口）**：调用方正确使用所需知道的一切——
  类型签名 + 不变量 + 顺序约束 + 错误模式 + 必需配置 + 性能特征
- **Implementation（实现）**：模块内部；与 **Adapter（适配器）** 区分——
  接缝是主题时用 adapter，否则用 implementation
- **Depth（深度）**：接口处的杠杆——调用方每学一单位接口能驱动多少行为
- **Seam（接缝）**：不改该处代码就能改变行为的位置——模块接口所在之处
- **Leverage（杠杆）**：调用方从深度获得——一份实现回报 N 处调用与 M 个测试
- **Locality（局部性）**：维护者从深度获得——变更/缺陷/知识/验证集中一处，
  修一次到处好

## 2. 深 vs 浅

- **深模块**：小接口 + 大实现（推荐）——复杂逻辑藏在后面
- **浅模块**：大接口 + 小实现（避免）——只是透传

设计接口时问：
- 能减少方法数量吗？
- 能简化参数吗？
- 能把更多复杂度藏进内部吗？

## 3. 原则

- **接口即契约**：把不变量/约束/错误模式写进接口（调用方只读接口就能用对）
- **接缝位置是设计决策**：放在哪 ≠ 后面放什么
- 适配器角色化描述（填哪个槽），不说实质
- 深度带来杠杆与局部性：改一处，影响集中，回归面小
- **可测性**：通过接口测试——深模块的测试少而强
- **AI 可导航**：清晰接口让 agent/人只看接口就能理解用法

## 4. 找加深机会

- 接口比实现还复杂 → 浅模块信号
- 多处重复"如何使用"的知识 → 应该收进接口/实现
- 调用方被迫了解内部细节 → 接口泄露，加深

## 5. 自查清单

- [ ] 术语精确（module/interface/implementation/seam/adapter）
- [ ] 模块深（小接口 + 大实现），无浅透传
- [ ] 接口含不变量/约束/错误模式
- [ ] 接缝位置经过设计（非顺手）
- [ ] 通过接口可测（测试少而强）
- [ ] 调用方与 agent 只看接口即会用

## 边界

- 深模块是理想不是教条：适配层/胶水代码天生浅，可接受。
- 与架构（模式）互补：架构定结构，深模块定模块内设计。
