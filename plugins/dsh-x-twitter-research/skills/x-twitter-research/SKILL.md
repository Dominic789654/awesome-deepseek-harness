# X/Twitter Research — X/Twitter 研究

用结构化流程做 X 社交倾听：先读后写，读公开信号，改账号的动作要显式批准。

## 何时用

- 研究 X 账号 / 阅读时间线
- 监控发布与启动信号
- 调查提及与舆论
- 审计 giveaway/抽奖活动
- 准备受控发帖（发布/回复/私信/关注等）

## 1. 输入先问清

- **目标**：研究 / 监控 / 支持分流 / 抽奖审计 / 动作准备
- **对象**：账号 handle、推文 URL、关键词、列表、趋势
- **时间窗**与新鲜度要求
- **是否有改账号的动作在范围内**（发布/回复/私信/关注/改资料）
- **密钥就绪**（读与动作工具需要 API key）

## 2. 工作流

1. 先**探索可用端点**（按目标匹配路由），不猜
2. **读**：账号/推文/趋势/监控/搜索数据 → 总结公开信号（发回复/战役前先总结）
3. **动作**：改账号的路由（发帖/回复/关注/媒体/监控/webhook）只显式批准后执行
4. **密钥**放环境变量，绝不进 prompt/issue/PR 评论/工具输入

## 3. 阅读优先原则

- 默认只读会话：动作开关保持关闭；只有**明确要发动作的会话**才开
- 先读后写：起草回复/战役前，先总结目标账号的时间线与信号
- 监控：设置关键词/账号监控，定时读更新（启动信号、竞品动态）
- 抽奖审计：核对规则、参与条件、中奖流程是否一致

## 4. 动作审批门控

- 发帖/回复/私信/关注等改账号动作 = 不可逆，先给人类看拟稿
- 批量/自动化动作：分批 + 预览 + 确认
- 记录已发动作（时间/内容/目标），便于回滚与复盘

## 5. 自查清单

- [ ] 目标/对象/时间窗已明确
- [ ] 先探索端点再读数据，先总结信号再起草
- [ ] 改账号动作已显式批准（非默认）
- [ ] 密钥在环境变量、未入任何文本
- [ ] 监控有更新节奏、抽奖审计有核对清单
- [ ] 已发动作有记录

## 边界

- X API 第三方服务（如 Xquik）需要 key 与配额，费用自理。
- 平台规则（频率限制、自动化政策）严格：动作节奏要保守合规。
