# To Questionnaire — 决策转问卷

把用户无法独自回答的事变成**问卷**：一份 Markdown 文档，
交给掌握知识的人异步填或会议一起填。收件人持有用户缺的知识，
问卷把它挖出来。

## 1. 盘问"发送方"，不盘问主题

只盘问用户关于**发送**的事（他们总能回答）：
1. **给谁？** 一次问清收件人角色/专业度/与用户的关系——
   决定语气与要带多少上下文。知道收件人是谁、他们知道什么
   用户不知道的，就完成
2. **要回什么？** 一次问清用户无法独自解决、需要从这个人得到的
   具体决策或事实。得到用户必须能走开去做的/能决定的具体清单，
   就完成
3. **写问卷**：问题瞄准步骤 1-2 的**缺口**，按文档结构写，
   存为 `to-questionnaire-<slug>.md` 并报告路径。
   步骤 2 列出的每项都有对应问题才算完成

## 2. 文档结构（发现式问卷）

- **Purpose**：为什么存在、赌在上面的决策
- **From / To / 答案怎么用**
- **Context**：一段话让没进过用户脑子的收件人进入状态
  （足够答好，不是一页）
- **How to answer**：截止时间与大致工作量；部分答案和
  "我不知道"也有用——不确定要标记而不是跳过
- **主题分组**：`##` 主题节，节内问题重要优先
  （异步可能只有一次机会）
- **单问题单想法**：每个问题一个想法，不复合；下方留答案栏；
  可能被误读或诱发敷衍答案的问题才加一行"为什么重要"

## 3. 自查清单

- [ ] 先盘问发送方（给谁/要回什么）
- [ ] 问题瞄准知识缺口
- [ ] 重要优先、按主题分组
- [ ] 单问题单想法 + 答案栏
- [ ] 步骤 2 的每项都有对应问题
- [ ] 存为文件并报告路径

## 边界

- 问卷是知识提取工具：收件人没答案时"我不知道"也是有效输出。
- 异步只有一次机会：问题宁多勿漏、顺序宁重勿轻。
