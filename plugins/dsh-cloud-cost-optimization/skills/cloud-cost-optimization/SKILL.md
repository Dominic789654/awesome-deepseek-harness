# Cloud Cost Optimization — 云成本优化

系统化降低云支出，同时保持性能与可靠性：可见性 → 合理规格 → 定价模型 → 架构。

## 何时用

- 降低云支出
- 资源合理规格（right-sizing）
- 实施成本治理
- 优化多云成本
- 满足预算约束

## 1. 框架：先可见，再优化

1. **可见性**：成本分配标签（tagging）落地、成本管理工具、预算告警、成本仪表盘
2. **合理规格**：分析利用率、缩容过度配置资源、自动扩缩、清理闲置资源
3. **定价模型**：预留容量、Spot/抢占式实例、节省计划、承诺使用折扣
4. **架构优化**：托管服务、缓存、优化数据传输、生命周期策略

## 2. AWS 定价模型速查

- **预留实例（RI）**：省 30-72%（对比按需）；1/3 年；全/部分/无预付；标准/可转换
- **节省计划（Savings Plans）**：Compute 类省约 66%、EC2 Instance 类约 72%；
  适用 EC2/Fargate/Lambda；跨实例族/区域/OS 灵活
- **Spot 实例**：最高省 90%；适合批处理/CI/无状态负载；风险 2 分钟中断通知；
  策略：与按需混用保弹性

## 3. 存储与数据优化

- S3 生命周期策略：热→IA→归档（Glacier）分层，旧数据自动降级
- 数据传出（egress）费用常被忽视：就近放置、CDN、压缩
- 快照/备份清理：保留策略 + 定期清理过期快照

## 4. 治理与持续优化

- 预算告警：按项目/环境设置阈值，超支即时通知
- 成本看板按团队/服务拆分（标签强制规范）
- FinOps 节奏：定期复盘（月度账单审查 + 闲置资源清理）
- 新架构评审带成本项：托管服务优先（省运维也常省成本）

## 5. 自查清单

- [ ] 成本标签全量落地，预算告警就位
- [ ] 过度配置资源已缩容，闲置资源已清理
- [ ] 稳态负载已用 RI/节省计划，弹性负载混用 Spot
- [ ] 存储分层与数据传出已优化
- [ ] 每月成本复盘有固定节奏
- [ ] 新项目评审包含成本项

## 边界

- 各云商（AWS/Azure/GCP/OCI）计费与折扣形态不同，按云商细则执行。
- 优化要防"省成本伤性能/可靠性"：SLA 与弹性优先，再谈省钱。
