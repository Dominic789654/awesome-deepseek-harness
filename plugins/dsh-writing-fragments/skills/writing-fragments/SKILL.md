# Writing Fragments — 写作探索

纯**探索**：扩大"可能写什么"的空间，不承诺结构。
承诺结构是**开采**（另一技能的工作）。跑一场盘问会话产出碎片，
关于用户想写的东西持续追问。强加阶段/大纲/文章结构超出范围。

## 1. 什么是碎片

任何可能活进最终文章的文字片段。**作者自己能读懂**即可——
不需要定义术语或让冷读者理解。标准是"这是不是好文字"，
不是"这是不是自洽论证"。

碎片刻意异构，例如：
- 想在某处用但还不知道放哪的锐句
- 带一行理由的主张
- 小场景：发生的事、代码片段、情境、类比
- 半想法："X 感觉像 Y，以后想清楚"
- 引语/对话/听到的一句话
- 凭感觉挂在一起的观察清单
- 抱怨、自白、笑点
- **领航词**：整个作品可挂靠的紧凑隐喻/造词
  （一个命名想法的词，如 *tracer bullets*/*fog of war*）

**领航词是最有价值的碎片**——承重墙：探索期命名对了，
它塑造结构、过渡、标题，在整个开采阶段持续回报。
对话反复绕一个想法时，推动为它造词。

小说家日记是模型：多年非结构化的观察，日后被挖作素材。
碎片就是观察。

## 2. 工作流

- 从用户说的**第一句话**（含初始 prompt）就开始捕获
- 会话双方浮现的碎片都追加进单一 markdown 文件
- 路径未定 → 问一次并记住
- 首次写入：顶部一个 H1 工作标题（可后改）+ 无其他
  （无元数据/目录/日期）

## 3. 自查清单

- [ ] 第一句话起就捕获碎片
- [ ] 碎片异构（金句/主张/场景/半想法/引语/领航词）
- [ ] 反复出现的想法已尝试造词（领航词）
- [ ] 无结构承诺（不建大纲/阶段）
- [ ] 单一文件追加、路径已记
- [ ] 工作标题置顶、无多余元数据

## 边界

- 探索与开采分开：碎片够了才交给塑形/节拍技能。
- 碎片的可读对象是作者本人——别为了冷读者过早打磨。
