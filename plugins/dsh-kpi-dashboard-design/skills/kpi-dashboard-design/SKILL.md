# KPI Dashboard Design — KPI 仪表盘设计

设计驱动业务决策的 KPI 仪表盘：选对指标、分层呈现、口径统一。

## 何时用

- 设计高管仪表盘
- 选有意义的 KPI
- 构建实时监控大屏
- 部门专属指标视图
- 改进现有仪表盘布局
- 建立指标治理

## 1. KPI 框架

| 层级 | 关注 | 更新频率 | 受众 |
|---|---|---|---|
| 战略 | 长期目标 | 月/季 | 高管 |
| 战术 | 部门目标 | 周/月 | 经理 |
| 运营 | 日常 | 实时/日 | 团队 |

**SMART KPI**：具体（定义清晰）、可测（可量化）、可达（现实目标）、
相关（对齐目标）、有时限（明确周期）。

## 2. 仪表盘层级

```
高管摘要（1 页）
├── 4-6 个头条 KPI + 趋势指标 + 关键告警
部门视图（销售/市场/运营/财务各自面板）
详细钻取（单指标详情 + 根因分析）
```

## 3. 最佳实践

**要**：
- 限制 5-7 个 KPI（聚焦重要的事）
- 展示上下文：对比/趋势/目标线
- 颜色一致：红=差、绿=好
- 支持钻取：摘要 → 详情
- 更新频率匹配指标特性

**不要**：
- 不展示虚荣指标（要可行动的）
- 不拥挤（留白帮助理解）
- 不用 3D 图表（扭曲感知）
- 不隐藏计算方法（口径文档化）

## 4. 指标治理

- **统一口径**：每个指标有定义/公式/数据源（防指标互相矛盾）
- 计算方法变更要记录版本与生效日期
- 告警阈值有依据（与目标/基准挂钩）
- 定期复核：指标仍对齐目标？仍可行动？

## 5. 实时监控模式

- 监控大屏：服务健康、请求吞吐、错误率（RED 指标）
- 实时 ≠ 高频刷新：按指标特性定刷新（状态指标秒级/趋势分钟级）
- 告警分级：P0/P1/P2 对应通知渠道与响应

## 6. 自查清单

- [ ] KPI 符合 SMART、5-7 个以内
- [ ] 三层层级（摘要/部门/钻取）清晰
- [ ] 每个指标有定义/公式/数据源（口径一致）
- [ ] 无虚荣指标、无拥挤、无 3D 图
- [ ] 上下文（对比/趋势/目标）齐全
- [ ] 告警有依据、实时刷新合理

## 边界

- 仪表盘是决策工具不是装饰：先定"谁看、做什么决定"再选指标。
- 指标口径不一致是仪表盘信任杀手——治理优先于炫技。
