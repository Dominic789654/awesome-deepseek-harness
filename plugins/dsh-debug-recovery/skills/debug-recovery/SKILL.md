# Debug Recovery — 调试与错误恢复

系统化调试 + 恢复：先复现、再定位根因、修根因、防回归。与
superpowers-essentials 的系统化调试互补（本技能更细：错误分类与恢复策略）。

## 1. 建立证据（先别猜）

- **复现**：最小复现路径；复现不了就问清楚触发条件，不猜。
- **收集**：完整错误原文、复现输入、实际输出 vs 期望输出、相关日志、
  最近变更（git log/diff）。
- **读全错误**：不只最后一行；堆栈/上下文常藏着根因。

## 2. 错误分类（决定策略）

| 类型 | 特征 | 策略 |
|---|---|---|
| 逻辑错误 | 输入对但输出错 | 修代码 + 补测试 |
| 数据错误 | 脏数据/迁移问题 | 数据修复 + 校验 |
| 环境错误 | 仅某环境出现 | 环境差异排查 |
| 集成错误 | 跨服务/依赖问题 | 契约检查 + 依赖升级/降级 |
| 性能问题 | 慢/卡 | 参考 performance 技能 |
| 偶发（flaky） | 时好时坏 | 竞态/时序/资源泄漏排查 |

## 3. 定位根因（系统化）

- **二分定位**：注释一半代码/配置 → 缩小范围。
- **加日志/断点**：在假设点打日志，验证数据流。
- **最小改动隔离**：一次只改一个变量，测一次。
- **检查近期变更**：git blame / 最近提交，多数 bug 是最近改动引入。
- **形成假设再验证**：列出 2-3 个候选根因，按概率排序逐一验证。

## 4. 恢复策略（按场景）

- **线上事故**：先回滚/降级止血（参考 runbook/shipping），再离线调查。
- **本地/开发**：直接修，但保持小步可回退（参考 incremental）。
- **数据损坏**：先备份，再修复脚本（可重复执行、幂等）。
- **无法立即修**：明确降级方案（功能开关关闭受影响路径）+ 记录 issue。

## 5. 修复与防回归

- **修根因不修症状**：找到"为什么坏"，不只让当前用例通过。
- **补回归测试**：先写复现测试（参考 tdd 的 Prove-It 模式）。
- **检查同类问题**：同一模式在别处是否也存在（grep 类似代码）。
- **记录**：修了什么、根因是什么、如何防复发（postmortem 如有价值）。

## 输出

```markdown
## 调试报告

- **现象**：…
- **复现**：…
- **根因**：…（证据：…）
- **修复**：…（行为变化：…）
- **防回归**：…（测试/检查）
- **未解决项**：…
```

## 边界

- 不无限调试：30 分钟无进展 → 停下来总结已知信息，向用户求助/换思路。
- 涉及生产数据/部署的操作需用户确认。
