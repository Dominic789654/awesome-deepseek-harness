# E2E Testing — 端到端测试

用 Playwright/Cypress 建可靠、快、可维护的 E2E 套件：测关键旅程、防回归、快速上线。

## 何时用

- 实现端到端自动化测试
- 调试 flaky/不稳定测试
- 测试关键用户工作流
- 搭建 CI/CD 测试流水线
- 跨浏览器测试
- 验证可访问性要求
- 建立 E2E 测试标准

## 1. 测什么 / 不测什么

**E2E 测**：关键用户旅程（登录/结账/注册）、复杂交互（拖拽/多步表单）、
跨浏览器兼容、真实 API 集成、认证流程。

**E2E 不测**：单元级逻辑（用单元测试）、API 契约（用集成测试）、
边角情况（太慢）、内部实现细节。

**金字塔定位**：单测多、集成中、E2E 少而精——E2E 是最后防线不是主战场。

## 2. 测试哲学与选择

- Playwright：跨浏览器内置（Chromium/Firefox/WebKit）、自动等待、Trace 视图
- Cypress：开发者体验好、时间旅行调试
- 选型按团队栈；关键能力：自动等待（少用 sleep）、可重试断言、trace/视频

## 3. 防 flaky 策略

- **固定选择器**：data-testid 优先，别依赖文本/位置
- **自动等待**元素就绪，不用固定 sleep
- 隔离测试数据：每个测试独立 setup/teardown（API 造数）
- 网络可控：拦截/桩外部请求（稳定 + 快）
- 串行依赖最小化：测试独立可并行
- 失败即证据：失败时截图 + trace，直接定位

## 4. CI 集成

- E2E 在 CI 跑：可并行分片（shard）提速
- 分环境：PR 冒烟（关键旅程）→ 主干全量
- 失败重试策略（flaky retry）但别掩盖真问题（统计 flaky 率）
- 产物：trace/视频/报告上传，失败可复盘

## 5. 可访问性与响应式

- 用 E2E 顺带验证 a11y（axe 集成）与响应式断点
- 键盘导航、ARIA 标签、对比度抽查
- 移动视口测试关键旅程

## 6. 自查清单

- [ ] E2E 只覆盖关键旅程，金字塔比例合理
- [ ] 选择器用 data-testid，无固定 sleep
- [ ] 测试数据隔离、外部请求可控
- [ ] CI 分片并行 + PR 冒烟/主干全量
- [ ] flaky 失败有 trace/视频证据
- [ ] a11y 与响应式纳入 E2E

## 边界

- E2E 慢且贵：覆盖面控制在关键业务路径，别替代单测。
- 工具版本差异（Playwright/Cypress API），按所选工具文档。
