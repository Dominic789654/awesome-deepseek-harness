# Teach — 教学与讲解

把主题在**教学工作区**里教给用户（跨多个会话的有状态请求）。

## 何时用

- 用户要学一个新技能/概念
- 需要把知识教到"长期掌握"而非临时了解
- 建立持续学习的工作区

## 1. 教学三要素

- **知识**：来自高质量、高信任的资源
- **技能**：基于知识的、高度相关的互动课程
- **智慧**：与其他学习者/实践者互动获得

RESOURCES.md 未充实前，专注找高质量资源——**别信参数化记忆**。
有些主题偏知识（理论物理），有些偏技能（瑜伽）——按主题配比。

## 2. 流畅度 vs 存储强度

- **流畅度**：当下检索的轻松感——可能造成"会了"的错觉
- **存储强度**：长期保留——真正的目标

用**合意困难**设计课程构建长期记忆：
- 检索练习（从记忆回忆）
- 间隔（时间上分散练习）
- 交错（技能练习混合相关主题）

## 3. 教学工作区

- `MISSION.md`：学习动机（锚定所有教学）
- `reference/*.html`：压缩的学习速查（cheat sheet/词汇表，可打印美观）
- `RESOURCES.md`：可探索的高质量资源清单
- `learning-records/*.md`：学习记录（类似 ADR——记录非显然的洞察，
  用于计算最近发展区）
- `lessons/*.html`：**课程** = 单一自包含 HTML，教一件紧扣使命的
  窄主题——教学的主要单元
- `assets/*`：可复用组件（样式表/测验组件/图表助手）
- `NOTES.md`：偏好与工作笔记

## 4. 课程设计

- **短而快完成**：学习者工作记忆很小，别超载
- **单次可见的胜利**：每课一个可叠加的具体收获
- **紧扣使命** + 在**最近发展区**内
- 美观（用户会回看复习，Tufte 风格干净排版）
- 链接其他课程/参考；推荐一个高质量一手来源；提醒可以追问

## 5. 组件复用

复用是默认：写课程前先读 `assets/`，从已有组件构建；
新东西写成组件再链接（不内联未来会重复的代码）。
共享样式表是第一个组件：让课程像一门课而非一堆一次性页面。

## 6. 自查清单

- [ ] 高质量资源先行（不信参数化记忆）
- [ ] 课程含检索/间隔/交错（合意困难）
- [ ] MISSION 锚定 + 每课紧扣使命
- [ ] 课程短、单胜利、在最近发展区
- [ ] 参考/资源/学习记录更新
- [ ] 组件复用（不重复造）

## 边界

- 教学是状态化长跑：记录学习状态（records）驱动后续会话。
- 输出形态（HTML 课程）可按学习者偏好调整，方法论不变。
