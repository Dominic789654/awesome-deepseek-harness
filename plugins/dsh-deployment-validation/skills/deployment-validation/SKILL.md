# Deployment Validation — 部署验证与配置管理

验证配置正确性、跨环境一致性、无密钥泄漏；部署后确认结果、必要时回滚。

## 何时用

- 验证配置文件（JSON/YAML/TOML/ini/env）
- 实现配置校验 schema
- 跨环境一致性检查
- 扫描配置中的密钥/敏感信息
- 部署后验证与回滚决策

## 1. 配置分析

- 找全配置文件（json/yaml/toml/ini/env/config.js 等）
- 按文件类型与所属环境分类
- 三查：**类型安全**（schema 校验）、**一致性**（跨环境差异）、
  **安全性**（密钥/敏感信息）

## 2. 安全扫描

- 正则模式扫描密钥（api_key/secret/password/token/aws_access 等）
- 区分"模式出现"与"真实密钥"（假阳性过滤：占位符/示例值）
- 发现真实密钥 → 高危告警：轮换 + 移入密钥管理/环境变量

## 3. 校验 schema 与自动化

- 每个配置文件配 schema（类型/必填/取值范围/枚举）
- 校验进 CI：配置变更未通过校验就阻断
- 环境模板化：基础 schema 复用，环境差异显式声明（dev/staging/prod）

## 4. 部署后验证

- 部署后验证清单：健康检查/版本号/关键指标/日志无错误
- 与预期不符 → 回滚决策：先评估影响面与回滚成本
- 验证结果记录（时间/环境/版本/检查项）

## 5. 自查清单

- [ ] 配置文件已全量盘点并分类
- [ ] schema 校验覆盖类型/必填/取值范围
- [ ] 密钥扫描无真实密钥泄漏（或已轮换）
- [ ] 跨环境差异显式且有意
- [ ] 校验自动化进 CI
- [ ] 部署后验证清单执行 + 回滚决策记录

## 边界

- 配置是"运行时真相"：schema 先行能挡大部分配置错误。
- 密钥治理是持续工程：扫描 + 轮换 + 入口限制三管齐下。
