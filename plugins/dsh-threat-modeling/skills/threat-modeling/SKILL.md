# Threat Modeling — 威胁建模

系统化可视化攻击路径：攻击树 + STRIDE 分类 + 缓解映射，为防御投资排优先级。

## 何时用

- 可视化复杂攻击场景
- 识别防御缺口与优先级
- 向干系人沟通安全风险
- 规划防御投资
- 渗透测试规划
- 安全架构评审

## 1. 攻击树结构

```
         [根目标]
       ┌────┴────┐
   [子目标1]  [子目标2]
   (OR 节点)  (AND 节点)
     │          │
  [攻击]     [攻击][攻击]
   (叶)       (叶) (叶)
```

- **OR 节点**（椭圆）：任一子节点达成目标
- **AND 节点**（矩形）：全部子节点都需达成
- **叶子**（框）：原子攻击步骤

## 2. 攻击属性（标注每个节点）

| 属性 | 说明 | 值 |
|---|---|---|
| 成本 | 所需资源 | $ / $$ / $$$ |
| 时间 | 执行时长 | 小时/天/周 |
| 技能 | 所需专业度 | 低/中/高 |
| 检测 | 被发现的可能 | 低/中/高 |

属性让"最值得防的路径"可量化：低成本+高影响+难检测优先。

## 3. STRIDE 威胁分类

- **S**poofing 假冒 / **T**ampering 篡改 / **R**epudiation 抵赖
- **I**nformation Disclosure 信息泄露 / **D**enial of Service 拒绝服务
- **E**levation of Privilege 提权

每个组件/数据流过一遍六类威胁 → 形成威胁清单。

## 4. 缓解映射

- 每条威胁 → 至少一条缓解措施（认证/加密/校验/限流/最小权限…）
- 缓解优先级 = 攻击树属性（成本低+检测难 → 优先）
- 无法缓解的接受风险要显式记录（残余风险）
- 定期更新：威胁态势演进，树不是静态文档

## 5. 最佳实践

**要**：目标清晰（攻击者想要什么）；穷尽攻击向量；属性标注；
专家验证（红队评审）；与缓解计划联动。
**不要**：不过度简化（真实攻击复杂）；不忽略 AND 依赖；
不忘记内部威胁（不全是外部攻击者）；不做静态文档；
不跳过缓解（树是为防御规划服务的）。

## 6. 自查清单

- [ ] 根目标 + 子目标 + 叶子完整，OR/AND 正确
- [ ] 每个节点有成本/时间/技能/检测属性
- [ ] STRIDE 六类都过了一遍
- [ ] 每条威胁有缓解映射 + 优先级
- [ ] 残余风险显式记录
- [ ] 红队/专家验证 + 定期更新

## 边界

- 威胁建模是过程不是一次交付：随架构演进持续更新。
- 与安全加固互补：建模发现问题，加固提供落地控制。
