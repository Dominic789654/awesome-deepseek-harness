# Browser Testing — 浏览器测试与 UI 验证

给 agent 一双"看浏览器"的眼睛：不再静态猜运行时，而是**验证**——
查看 DOM、读控制台、分析网络、采集性能。

## 何时用

- 构建/修改任何渲染在浏览器里的东西
- 调试 UI 问题（布局、样式、交互）
- 诊断控制台错误/警告
- 分析网络请求与 API 响应
- 性能剖析（Core Web Vitals、绘制时间、布局偏移）
- 验证修复在浏览器里真的生效
- 通过 agent 做自动化 UI 测试

**不用**：纯后端改动、CLI 工具、不在浏览器运行的代码。

## 验证手段（按可用性）

1. **浏览器自动化工具**（优先）：若环境有 DevTools/浏览器自动化能力
   （如 browser-skill、Playwright MCP），用它打开页面真实检查。
2. **静态+运行时推断**：读源码 + 用户提供的截图/控制台输出。
3. **用户协作**：给出精确的验证步骤，让用户执行并反馈。

## 验证清单（UI 问题排查）

- **DOM**：元素是否存在？结构和预期一致吗？
- **控制台**：有报错/警告吗？堆栈指向哪里？
- **网络**：请求成功吗？响应正确吗？有无 4xx/5xx、超时？
- **布局**：元素尺寸/位置/溢出？响应式断点行为？
- **交互**：点击/输入/滚动是否生效？事件是否绑定？
- **性能**：LCP/CLS/INP 达标吗？有无明显卡顿/布局抖动？

## 修复验证闭环

1. **复现**：在浏览器里复现问题（截图/报错原文）。
2. **假设**：基于证据形成根因假设（参考 debug-recovery）。
3. **修复**：改代码。
4. **验证**：在浏览器里重测同一场景，确认修复生效且无新问题。
5. **回归**：关键路径补自动化检查（如 E2E 冒烟）。

## 输出

```
## 浏览器验证报告

- **页面/场景**：…
- **复现**：…
- **发现**：<DOM/控制台/网络/性能 逐项>
- **根因假设**：…
- **修复**：…（在浏览器验证通过：…）
- **残留问题**：…
```

## 边界

- 浏览器能力依赖环境（MCP/自动化工具）；没有时如实说明，用静态+协作验证。
- 截图/录制只作验证证据，不替代代码审查。
- 与 a11y-audit 配合：UI 验证时顺带查无障碍。
