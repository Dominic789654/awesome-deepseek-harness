# Recsys Pipeline — 推荐/排序流水线

生产里的多数"推荐系统"不是花哨 ML，而是**流水线**：从一个或多个来源
取候选、富化元数据、剔除不合格、给其余打分、排序取 Top K、触发异步副作用。
打分函数与物品会变；流水线形状不变。

## 何时用

- 构建返回"（用户/上下文）的 Top K"的任何系统
- 设计/重构个性化流（内容/搜索结果/通知）
- 把 LLM/ML 打分器包进流水线（来源/富化/过滤/副作用）
- 多动作预测（可调权重，替代单一相关分）
- RAG 检索重排（便宜检索 → 昂贵重排）
- 任务优先级/告警分流系统

## 六阶段框架

| 阶段 | 职责 | 并行 |
|---|---|---|
| 1 Source | 从一个或多个来源取候选 | 多源并行 |
| 2 Hydrator | 富化候选元数据（过滤与打分所需） | 独立富化器并行 |
| 3 Filter | 剔除不合格（资格/规则） | — |
| 4 Scorer | 给剩余候选打分 | — |
| 5 Selector | 排序取 Top K | — |
| 6 SideEffect | 触发异步副作用（日志/埋点/通知） | 异步 |

## 设计纪律

- **阶段可组合**：每阶段独立、可替换（打分器换不影响管道形状）
- 打分与物品分离：换场景只换 Source 与 Scorer
- 并行边界清晰：Source/Hydrator 天然并行，Filter/Scorer 保序
- 副作用异步化：不阻塞主路径返回
- 候选上限：每阶段控制规模（来源限制 → 过滤 → 打分成本可控）

## 典型落地

- 内容流：多来源候选 → 富化 → 资格过滤 → 个性化打分 → Top K → 埋点
- RAG 重排：BM25/向量召回（便宜）→ 交叉编码器重排（贵）
- 通知分流：候选通知 → 过滤静音 → 紧急度打分 → 限流选取 → 推送
